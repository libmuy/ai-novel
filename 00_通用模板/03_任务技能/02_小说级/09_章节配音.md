# 章节配音技能

> 把章节正文用 TTS 读成音频存档，供作者「听稿校对」或「校验辅助」。工具在
> `02_工具/01_小说通用工具/tts_chapter.py`。
> **本技能是 `tts_chapter.py` / `serve_audio.py` 用法与局限的唯一权威**（其它文件只引用、不复述）。

## 触发条件

用户要求配音、朗读、TTS、生成音频、有声、听稿；或某章正文在 `00_进度.json` 转「定稿」后；或用户明确要求生成音频用于校验（无论正文状态）。

## 前置

- 本章正文 `10_正文/…/章{C}.md` 需在 `00_进度.json` 里登记。状态为「定稿」或「待校验」时均可配音；「草稿」状态需用户明确要求用于校验方可配音。
- `edge` 后端首次使用前跑一次 `bash 02_工具/01_小说通用工具/tts/setup.sh`
  （在 `02_工具/.venv` 装 `edge-tts`）。`openai` 后端无 pip 依赖。

## 流程

1. 读 `00_进度.json` 确认本章正文状态。若为「定稿」或「待校验」则继续；若为「草稿」，需用户明确要求用于校验方可继续，否则停下并上报。
2. （可选）先 `--dry-run` 看清洗后的场景数与字数：
   ```
   python3 02_工具/01_小说通用工具/tts_chapter.py --chapter-dir <本章工作区目录> --dry-run
   ```
3. 实跑：
   ```
   python3 02_工具/01_小说通用工具/tts_chapter.py --chapter-dir <本章工作区目录>
   ```
   - 后端/音色/语速默认取 `02_工具/00_系统级/tts.config.toml`；本书差异写
     `05_工作区/02_状态/02_技能/本书技能配置.md`「配音参数」节，或用 `--backend/--voice/--rate` 覆盖。
   - 幂等：源文本与参数未变则打印 `skipped: unchanged`；需重配用 `--force`。
   - 退出码 2（后端不可用）→ 上报用户，不静默放行。
4. 核对结果 JSON 的 `scene_count` 与正文场景数（`※` 分隔段数）一致；试听确认音色、
   场景间停顿正常。
5. 「已配音」的记录落在 `03_音频/章{C:04d}.json` manifest 里（见下「产出」），不再写回 `00_进度.json`——它只存成熟度，没有叙事字段。

## 产出

- 音频 `<本章工作区>/03_音频/章{C:04d}.mp3`（`.gitignore` 已排除 `.mp3`）
- manifest `<本章工作区>/03_音频/章{C:04d}.json`（入库，留「哪章配过音、什么音色」记录）

## 试听 / 订阅 / 审查

`python3 02_工具/01_小说通用工具/serve_audio.py <小说目录>` 起本地服务：单页审查台，
侧栏「工作区 / 规划 / 正文」三分区，按全书→部→卷→章逐级浏览，右侧预览文件、
工作区分区还能发指令（细纲/正文提示词、冷读、配音、回填）；`/feed.xml` 是播客
RSS（手机播客 App 订阅，自动下载 + 记进度）。按需跑、Ctrl-C 停；API 与常驻方式
见下「工具参考」。

## 禁止

- 不给「草稿」状态的章节配音，除非用户明确要求用于校验。
- 后端全不可用时不静默跳过——上报用户。
- 不把 `03_音频/` 当正式小说数据引用（它是交付物/派生物，不进设定/规划/正文引用链）。

## 工具参考

### `tts_chapter.py` 后端

`02_工具/00_系统级/tts.config.toml` 的 `backend` 字段四选一：

- `edge`（默认）— 微软 Edge 在线 `edge-tts` CLI，免费无 key、中文旁白音色最好、直出 MP3、不需 ffmpeg
- `openai` — OpenAI 兼容 `/v1/audio/speech`，纯 urllib，供日后 `ai-station.local` 自建 TTS 服务
- `piper` — Pi 本机离线
- `auto` — 探测 openai 端点 → edge → 都不行退出码 2

付费端点密钥走环境变量或 gitignore 的 `tts.secret.toml`（体例同 `llm.secret.toml`）。

正文预处理只剥离场景分隔符 `※`（及 `＊`/`***`）、防御性去掉标题行/frontmatter/HTML 注释，
中文标点原样保留。按场景分段合成、字节拼接为整章一个文件（`--per-scene` 则每场景一个）。
manifest 记源 sha256 + 后端 + 音色 + 语速，用于幂等。退出码：`0` 正常 / `1` 路径参数错 /
`2` 后端不可用（不写文件、不静默放行）。

**局限**：

- ⚠️ `edge` / `openai` 这两个**在线后端会把正文文本发往对应服务器**——未公开的稿件请自行判断是否可接受。
- 字节拼接非母带级（够听稿）。
- 多音字 / 生造术语（碎灵石、命灵痕…）读音暂不校正。

### `serve_audio.py` API 与安全

纯标准库、无依赖。`<小说目录>` = 含 `10_正文/` 与 `05_工作区/` 的那层。前端是
`serve_ui/`（静态单页，`/` `/app.js` `/nocturne.css`），数据全走 `/api/*`：

- `GET /api/book` 书结构（部→卷→章，标题/状态标签）；`GET /api/level` 某一级的文件分组 + 下级列表
- `GET/PUT/DELETE /api/file` 读 / 保存（改名即另存为）/ 删除（移到 `.trash/`）
- `GET /api/backfill-targets` + `POST /api/backfill` 把已打开文件写回规划/正文正式位置，可选顺带冷读
- `POST /api/jobs` + `GET /api/jobs/<id>` 后台任务（细纲/正文提示词、冷读、配音；大纲类/校验类任务占位 501，未实现）
- `GET /feed.xml`；`GET /audio/<部>/<卷>/<章>[/<场>].mp3`（Range 断点续传）；`/health`

RSS 链接默认按请求 Host 头拼（局域网免配置），反代 / mDNS 名走 `--base-url`。
feed 条目 pubDate 由「部/卷/章」号合成，严格按阅读顺序，重生成某章不打乱订阅端。

页面里放音频走**常驻迷你播放条**：`index.html` 的 `#miniplayer` 与 `<audio>` 刻意放在 `#app`
之外（`render()` 只清空 `#app`），所以切章 / 切区 / 任务轮询的重渲染都不打断播放；换曲直接替换
当前曲目。锁屏与控制中心的封面、标题、进度、播放暂停走 Media Session，不支持的旧浏览器静默
降级（只少锁屏控制，播放照常）。

> ⚠️ **安全**：默认监听 `0.0.0.0`、**无鉴权**，仅适合可信局域网。写入一律做 realpath 越界
> 校验，只允许落在 `05_工作区/03_规划/10_正文` 三棵树；状态树 `05_工作区/02_状态/01_最新状态`
> 只读（改状态须走 `merge_chapter_state.py`，不经本服务）。所有非 GET 请求须带
> `X-Review-UI: 1` 请求头（简单 CSRF 防护）。只想浏览/播放、不想开写入与任务接口时加
> `--read-only`。

### 常驻服务（可选）

```bash
sudo bash 02_工具/01_小说通用工具/tts/install-service.sh [--novel-dir … --port … --name …]
```

装成 systemd 服务（模板 `serve-audio.service.in`）——开机自启、崩溃重拉，带资源兜底
（`MemoryMax=1G` / `CPUWeight=20` / `Nice=10`，v3 起后台任务会跑 build_prompt.py 等子进程，
比纯浏览吃得多）与沙箱加固（`ProtectSystem=strict` 只读 + `ReadWritePaths=<小说目录>` 单独放开、
`NoNewPrivileges` 等）。空闲常驻仍是几十 MiB RSS、CPU≈0，只在有任务在跑时才吃资源。
多本小说各用 `--name <后缀>` + 不同 `--port`。卸载：`… install-service.sh --uninstall [--name …]`。
