# 章节配音技能

> 把章节正文用 TTS 读成音频存档，供作者「听稿校对」或「校验辅助」。工具在
> `02_工具/01_小说通用工具/tts_chapter.py`。
> **本技能是 `tts_chapter.py` / `serve_audio.py` 用法与局限的唯一权威**（其它文件只引用、不复述）。

## 触发条件

用户要求配音、朗读、TTS、生成音频、有声、听稿；或某章正文在 `00_进度.md` 转「定稿」后；或用户明确要求生成音频用于校验（无论正文状态）。

## 前置

- 本章正文需在 `00_进度.md`「正文与状态」表对应 `10_正文/…/章{C}.md` 行有记录。状态为「定稿」或「待校验」时均可配音；「草稿」或「待修改」状态需用户明确要求用于校验方可配音。
- `edge` 后端首次使用前跑一次 `bash 02_工具/01_小说通用工具/tts/setup.sh`
  （在 `02_工具/.venv` 装 `edge-tts`）。`openai` 后端无 pip 依赖。

## 流程

1. 读 `00_进度.md` 确认本章正文状态。若为「定稿」或「待校验」则继续；若为「草稿」或「待修改」，需用户明确要求用于校验方可继续，否则停下并上报。
2. （可选）先 `--dry-run` 看清洗后的场景数与字数：
   ```
   python3 02_工具/01_小说通用工具/tts_chapter.py --chapter-dir <本章工作区目录> --dry-run
   ```
3. 实跑：
   ```
   python3 02_工具/01_小说通用工具/tts_chapter.py --chapter-dir <本章工作区目录>
   ```
   - 后端/音色/语速默认取 `02_工具/00_系统级/tts.config.toml`；本书差异写
     `05_工作区/02_状态/02_技能/本书技能配置.md`「配音参数」节，或用 `--backend/--voice/--rate` 覆盖。
   - 幂等：源文本与参数未变则打印 `skipped: unchanged`；需重配用 `--force`。
   - 退出码 2（后端不可用）→ 上报用户，不静默放行。
4. 核对结果 JSON 的 `scene_count` 与正文场景数（`※` 分隔段数）一致；试听确认音色、
   场景间停顿正常。
5. 在 `00_进度.md`「正文与状态」表该行「说明」补一句「已配音（<音色> / <日期>）」。

## 产出

- 音频 `<本章工作区>/03_音频/章{C:04d}.mp3`（`.gitignore` 已排除 `.mp3`）
- manifest `<本章工作区>/03_音频/章{C:04d}.json`（入库，留「哪章配过音、什么音色」记录）

## 试听 / 订阅

`python3 02_工具/01_小说通用工具/serve_audio.py <小说目录>` 起本地服务：首页选
「正文 / 工作区」→ 章节列表 →「读 / 听」；`/feed.xml` 是播客 RSS（手机播客 App
订阅，自动下载 + 记进度）。按需跑、Ctrl-C 停；路由与常驻方式见下「工具参考」。

## 禁止

- 不给「草稿」或「待修改」状态的章节配音，除非用户明确要求用于校验。
- 后端全不可用时不静默跳过——上报用户。
- 不把 `03_音频/` 当正式小说数据引用（它是交付物/派生物，不进设定/规划/正文引用链）。

## 工具参考

### `tts_chapter.py` 后端

`02_工具/00_系统级/tts.config.toml` 的 `backend` 字段四选一：

- `edge`（默认）— 微软 Edge 在线 `edge-tts` CLI，免费无 key、中文旁白音色最好、直出 MP3、不需 ffmpeg
- `openai` — OpenAI 兼容 `/v1/audio/speech`，纯 urllib，供日后 `ai-station.local` 自建 TTS 服务
- `piper` — Pi 本机离线
- `auto` — 探测 openai 端点 → edge → 都不行退出码 2

付费端点密钥走环境变量或 gitignore 的 `tts.secret.toml`（体例同 `llm.secret.toml`）。

正文预处理只剥离场景分隔符 `※`（及 `＊`/`***`）、防御性去掉标题行/frontmatter/HTML 注释，
中文标点原样保留。按场景分段合成、字节拼接为整章一个文件（`--per-scene` 则每场景一个）。
manifest 记源 sha256 + 后端 + 音色 + 语速，用于幂等。退出码：`0` 正常 / `1` 路径参数错 /
`2` 后端不可用（不写文件、不静默放行）。

**局限**：

- ⚠️ `edge` / `openai` 这两个**在线后端会把正文文本发往对应服务器**——未公开的稿件请自行判断是否可接受。
- 字节拼接非母带级（够听稿）。
- 多音字 / 生造术语（碎灵石、命灵痕…）读音暂不校正。

### `serve_audio.py` 路由与安全

纯标准库、无依赖。`<小说目录>` = 含 `10_正文/` 与 `05_工作区/` 的那层。

- `/` 首页（正文 / 工作区 两个入口 + 播客订阅地址）
- `/text` 正文章节列表；`/text/<部>/<卷>/<章>/read` 渲染正文（`?raw=1` 出纯文本）；`…/listen` 内嵌播放器
- `/work` 工作区章节列表；`/work/<部>/<卷>/<章>/read` 该章工作区文件浏览器（`?f=<相对路径>`）；`…/listen` 同一份音频
- `/feed.xml` 播客 RSS；`/audio/<部>/<卷>/<章>[/<场>].mp3`（Range 断点续传）；`/health`

RSS 链接默认按请求 Host 头拼（局域网免配置），反代 / mDNS 名走 `--base-url`。
feed 条目 pubDate 由「部/卷/章」号合成，严格按阅读顺序，重生成某章不打乱订阅端。

> ⚠️ **安全**：默认监听 `0.0.0.0`、**无鉴权**，仅适合可信局域网。章节定位只由整数部/卷/章/场号
> 拼装；工作区文件浏览器对 `?f=` 做 realpath 越界校验；均无目录穿越。

### 常驻服务（可选）

```bash
sudo bash 02_工具/01_小说通用工具/tts/install-service.sh [--novel-dir … --port … --name …]
```

装成 systemd 服务（模板 `serve-audio.service.in`）——开机自启、崩溃重拉，带资源兜底
（`MemoryMax=128M` / `CPUWeight=20` / `Nice=10`）与沙箱加固（`ProtectSystem=strict` 只读、
`NoNewPrivileges` 等）。空闲常驻约 24 MiB RSS、CPU≈0。多本小说各用 `--name <后缀>` +
不同 `--port`。卸载：`… install-service.sh --uninstall [--name …]`。
