# 项目状态审计技能

> **本文件是 `audit_consistency.py` 与 `audit_rules.py` 输出的解读权威**：脚本产出的全部规则代码（`state_drift`/`state_object_unregistered`/`state_field_undeclared`/`chapter_opener_drift`/`PLAN_BEAT001`~`006`/`LEXICON000`/`LEXICON001`/`workspace`、`FS001`~`FS005`、`PROGRESS001`~`003`、`RULE001`~`RULE007` 等）的严重级别与触发条件定义，均以本文件「## 审查规则代码目录」为准；其它文件（含 `AGENTS.md`）如需提及这些规则代码，只可写「见本文件」的指针，不得复述定义。

## 触发条件

用户要求查看项目进度、审计成熟度、确认当前阻断或检查目录状态时执行。

## 流程

1. 读取当前小说 `00_进度.md`。
2. 核对状态值、目标路径、实际文件和父索引。
3. 区分待生成、草稿、待校验、定稿和结构缺失。
4. 检查前置依赖，列出可执行和被阻断的任务。
5. 输出问题、证据、下一步和验证命令；默认只读。

## 禁止

不自动提升成熟度，不用文件存在代替内容定稿，不修改小说数据。

## 输出

状态摘要、已完成项、阻断项、异常项、推荐下一步、验证结果。

### 伏笔登记与排期（`foreshadow` / `foreshadow_schedule`）

> `foreshadow` 只管「FH 号有没有在总纲登记」；`foreshadow_schedule` 管**排期到没到期**——
> 伏笔册里写着「埋设位置」「拟回收卷/章」「本卷回收章节」「执行状态」，到期与否本来就是可算的。
> 进度一律按**正文是否已落位**判断，不看成熟度。

| 规则代码 | 严重级别 | 触发条件 |
|---|---|---|
| `FS001` | warning | `@伏笔.FH-xxx` 引用未在 `03_规划/00_伏笔总纲.md` 登记 |
| `FS002` | info | 伏笔总纲不存在，无法校验 FH-ID 全局唯一性 |
| `FS003` | warning | **埋设逾期**：伏笔册说埋在某章，该章正文已落位，但该章细纲里找不到这个 FH（正文禁止出现 `@引用`，所以只能在细纲层判断） |
| `FS004` | warning | **回收逾期**：拟回收的卷/章已写完，卷册回收表里该 FH 的执行状态却不含「已回收」。卷级粒度按该卷【章节节拍表】末章是否已写判断；取不到末章的卷不参与判断 |
| `FS005` | warning | **无回收计划**：本卷新埋的 FH，「拟回收卷/章」为空 |

**刻意不做**「总纲状态 vs 卷册执行状态」对照——阶段性回收是合法的
（卷册可记「已回收（阶段性：…深层来历仍悬）」而总纲仍记「活跃」，两者都对），
写成规则只会制造假阳性。这一项仍归人工，见技能 `05_伏笔回收校验.md`。

### 进度表对账（`progress`，`PROGRESS001`~`003`）

> `00_进度.md` 混着两类信息：**成熟度与裁决**（人的判断，不可推导）＋ **文件在不在 /
> 多少字 / 跑了几轮 / 折叠到哪**（可推导）。后一半已物化成派生视图
> `05_工作区/02_状态/05_进度派生视图.md`（`progress_report.py --write` 生成，
> 文件头注明派生·非权威，符合 `00_系统架构规范.md` §二·A 第 2 条）；
> 本规则负责前一半与事实矛盾时报警。

| 规则代码 | 严重级别 | 触发条件 |
|---|---|---|
| `PROGRESS001` | error | 进度表声明了成熟度的 canonical 产出（`01_设定/`｜`02_数据库/`｜`03_规划/`｜`10_正文/`）文件不存在。含 `0N`/`NN`/`XX` 等通配写法的路径不参与对账 |
| `PROGRESS002` | warning | 章节细纲 / 正文已落位，进度表却完全没登记——**这正是本文件历来滞后的方式** |
| `PROGRESS003` | warning | 声明的成熟度超前于流水线事实：标「定稿」却缺 `01_状态履历.md` / 有履历但未折叠进 `01_最新状态/` / 标「定稿·待校验」却无 `## 冷读` 记录 |

**全景表**：`python3 02_工具/01_小说通用工具/progress_report.py <小说目录> [--write]`
（`--write` 刷新派生视图；不加只打印对账）。

### 规则层审计（`audit_rules.py`，`RULE001`~`RULE007`）

> 审的是**规则层自身**（`00_通用模板/` + `AGENTS.md` + `README.md`），不是小说数据——
> 依据 `00_系统架构规范.md` §二·A【规则层自身也适用本原则】。
> 命令：`02_工具/00_系统级/audit_rules.py [仓库根] [--format json|text] [--rule RULE00N] [--strict]`；
> 豁免登记在 `02_工具/00_系统级/rules_audit.config.toml`。

| 规则代码 | 严重级别 | 触发条件 |
|---|---|---|
| `RULE001` | error | 规则层反引号里的 Markdown 文件路径引用指向不存在的文件（死链）。占位符 / 已废止旧名在配置里登记豁免 |
| `RULE002` | warning | 索引声明的文件数与实际目录不符（如 `99_速查手册` 的「写作规则（N 个）」） |
| `RULE003` | error | 技能索引 ↔ 技能文件不是双向一一对应（技能不进索引 = 按「技能发现协议」永远找不到它） |
| `RULE004` | warning | 派生切片长出了权威版没有的小节。切片是有损压缩，**只许少、不许多** |
| `RULE005` | error | §二·A 权威位置表点名的权威文件不存在 |
| `RULE006` | warning | 同一段规范正文（≥25 字）逐字出现在多个规则文件——§二·A 描述的病根本身。「见 `<权威文件>`」式的指针句不计 |
| `RULE007` | error | 工具里硬编码的数据路径在骨架模板和所有实有小说里都落不了地（改名漏改） |

**一键三关**：`02_工具/00_系统级/check.sh [--strict] [--novel <书名目录>]` = 单元测试 + 规则层审计 + 各小说数据审计，提交前跑它。

## 局限说明

脚本对 `00_进度.md` 中各分类的权威产出路径（如 `02_数据库/02_地理区域/`）存在硬编码耦合，用于定位「源分类成熟度」表行；若数据库分类目录调整，需同步更新脚本内 `CATEGORY_KEYWORD_IN_PROGRESS`（与 `STANDARD_TOP_DIRS`）。
