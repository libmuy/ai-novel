# 章节回溯修改技能

## 触发条件

需要改动**已定稿的早期章节情节**，且该改动会影响状态时执行。典型场景：

- 改早期章节里角色的伤势/消耗/战利品/突破/关系/所在地/持有/财务结果；
- 让某角色在更早/更晚的章节才死亡、退场、回归；
- 调整某物品的损毁/易主时点；
- 修正早期章节履历中的错记、漏记。

用户提到「回溯修改」「改早期章节」「重算状态」「重折全局状态」时命中本技能。

> 只改**当前最新章**的状态，用 `03_章节状态对账.md`，不要用本技能。

## 前置认知

- 状态唯一权威存储是 `04_全局状态/`（每对象一文件）。没有逐章 `03_本章初始状态.md`。
- `04_全局状态/` == 冻结基线 `05_工作区/00_全局/00_基线状态/` ⊕ 全部 `04_本章状态履历.md` 的折叠。
- 回溯 = 改某一（或几）章的 `04_本章状态履历.md` → 从基线**全量重折** → 覆盖 `04_全局状态/`。

## 标准操作流程

1. **定位并修改**：
   - 按新情节修订相关章 `10_正文/` 与事件卡；
   - 更新相关章 `04_本章状态履历.md`：增删/修正「对象ID·字段·类型·值」行 + 元数据列
     （章节号 / 变更时间 / 变更类型）。前 4 列语法必须合规
     （运算-数值 `+N/-N`、运算-列表 `+X,-Y`、运算-枚举写目标值、描述写自由文本）。
   - 若某章要写**新章正文**又需要「该章开篇时的世界状态」：
     `python3 02_工具/build_state_snapshot.py --at-chapter <该章目录>`（只读、不调 LLM）。

2. **dry-run 重折复核（必做，不可跳过）**：
   ```
   python3 02_工具/rebuild_global_state.py <小说目录> --dry-run
   ```
   - 打印从基线重折后 `04_全局状态/` 的全部 diff；
   - 若报「有未冻结的描述字段变更」：说明你改动/新增了描述行。加 `--merge-pending`
     让脚本对这些章各调一次 LLM 合并（需 `02_工具/llm.config.toml` + key）：
     ```
     python3 02_工具/rebuild_global_state.py <小说目录> --dry-run --merge-pending
     ```
   - 有任何不符预期：回第 1 步继续修履历，重跑 dry-run，直到 diff 合理。

3. **正式执行**（确认无误后去掉 `--dry-run`，建议加 `--backup`）：
   ```
   python3 02_工具/rebuild_global_state.py <小说目录> --merge-pending --backup
   ```
   （无描述变更时可省略 `--merge-pending`。）

4. **一致性复查**：
   ```
   python3 02_工具/audit_consistency.py <小说目录> --format text
   ```
   - `state_drift`：仍报不一致说明还有对象文件被手改、或有章漏改 → 修正后回第 2 步；
   - `cascade_terminal_conflict` / `cascade_item_terminal_conflict`：角色终态（死亡/退场）
     或物品终态（损毁/易主）之后仍被后续章节变更 → 修对应章 `04` 履历，回第 2 步；
   - `workspace_state_type_mismatch` / `global_state_type_mismatch`：类型列与字段词表不符 → 按词表订正。

5. **卷末快照重建**（若涉及整卷）：
   ```
   python3 02_工具/build_state_snapshot.py --volume-dir <卷目录>
   ```

## 禁止

- 不跑 `--dry-run` 直接重折（覆盖不可逆）。
- 不手工编辑 `04_全局状态/` 或 `00_基线状态/` 下任何文件（一律脚本覆盖写入）。
- 写第 1 章之后不得改 `00_基线状态/`。
- 只改源头章的 `04` 履历让脚本重折，不去「凑」`04_全局状态/` 的结果。
- 不把身份设定写入动态状态表。
