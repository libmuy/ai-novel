# 章节回溯修改技能

## 触发条件

需要改动**已定稿的早期章节情节**，且该改动会影响状态链时执行。典型场景：

- 改早期章节里角色的伤势/消耗/战利品/突破/关系/所在地/持有/财务结果；
- 让某角色在更早/更晚的章节才死亡、退场、回归；
- 调整某物品的损毁/易主时点；
- 修正早期章节履历中的错记、漏记。

用户提到「回溯修改」「改早期章节」「重算状态链」「级联重放」时命中本技能。

> 只改**当前最新章**的状态，用 `03_章节状态对账.md`，不要用本技能。

## 标准操作流程

1. **定位起始章**：确定被修改情节所在的章目录
   `05_工作区/《部》/《卷》/《章》/`。

2. **改正文 + 改本章履历**：
   - 按新情节修订该章 `10_正文/` 对应章节与相关事件卡；
   - 更新该章 `04_本章状态履历.md`：增删/修正「对象ID·字段·类型·值」行，
     并补齐元数据列（章节号 / 变更时间 / 变更类型：新建·修改·移除）。
   - 前 4 列语法必须合规（运算-数值 `+N/-N`、运算-列表 `+X,-Y`、运算-枚举写目标值）。

3. **dry-run 级联复核（必做，不可跳过）**：
   ```
   python3 02_工具/rebuild_from_chapter.py <起始章目录> --dry-run
   ```
   - 逐章打印后续每个 `03_本章初始状态.md` 的 diff 与 `04_全局状态/` 同步计划；
   - 描述类字段变更会打印「旧值 vs 新值」——逐条确认没有信息丢失；
   - 有任何不符预期：回到第 2 步继续修履历，重跑 dry-run，直到全部 diff 合理。

4. **正式执行**：确认无误后去掉 `--dry-run`（建议加 `--backup`）：
   ```
   python3 02_工具/rebuild_from_chapter.py <起始章目录> --backup
   ```
   - 交互确认后，覆盖后续各章 `03_本章初始状态.md`；
   - 描述类字段逐条询问是否覆盖（选 `n` 保留旧值，人工合并后再重跑）；
   - **选 `n` 保留旧值后，必须把最终确定的文本回写进该字段所在章的 `04_本章状态履历.md`**
     （把「值」列改成人工合并后的最终描述）。否则 `audit_consistency.py` 的 `chain_drift`
     会因为「重放结果 ≠ 存盘 03」而持续误报。
   - 重放结束自动对最终终态执行一次 `--sync-global`，刷新 `04_全局状态/`。

5. **一致性复查**：
   ```
   python3 02_工具/audit_consistency.py <小说目录> --format text
   ```
   - 重点看 `cascade_terminal_conflict` / `cascade_item_terminal_conflict`：
     角色终态（死亡/退场）或物品终态（损毁/易主）之后仍被后续章节变更 → 必须修正；
   - 看 `chain_drift`：若仍报某章 `03` 与重放结果不一致，说明还有 `03` 被手改未回写、
     或有更早的受影响章没纳入本次重放范围 → 扩大起始章范围回第 3 步重跑；
   - 看 `workspace_state_type_mismatch`：履历「类型」列与字段词表不符 → 按词表订正；
   - 有冲突：修对应章节 `04` 履历，回第 3 步重跑。

6. **卷末快照重建**（若涉及整卷）：
   ```
   python3 02_工具/build_state_snapshot.py --volume-dir <卷目录>
   ```

## 禁止

- 不跑 `--dry-run` 直接级联覆盖（级联覆盖不可逆）。
- 不手工编辑 `04_全局状态/` 下文件（一律脚本覆盖写入）。
- 不修改后续章节 `03_本章初始状态.md` 来「凑」结果——只改源头章的 `04` 履历，让脚本重算。
- 不把身份设定写入动态状态表。
