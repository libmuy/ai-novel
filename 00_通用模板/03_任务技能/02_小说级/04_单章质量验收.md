# 单章质量验收技能

> 用户实验证明：写正文的那个模型自查会替自己找补；**换一批模型冷读、不看它的思考过程，
> 才挑得出前后矛盾/不闭合/脑补/穿帮**。本技能把「顺手自查」换成「确定性检查 + 多模型冷读循环」。

## 触发条件

用户要求单章验收、正文质检、章节检查、质量检查，或正文/细纲刚从云端落位为草稿时执行。

## 分工

- **冷读**（找问题）：评审器池——`opencode`（OpenCode CLI 免费模型，默认开）∥ `local_qwen`（`"auto"` 探测 `ai-station.local:8080`，活着才加）∥ `claude_subagent`（默认关，`true` 时脚本只置 `claude_subagent_requested=true`，由主 Agent 另 spawn 只喂正文的 general-purpose subagent）。由 `review_manuscript.py` 编排，见 `02_工具/00_系统级/review.config.toml`。两家外部评审器（`opencode`/`local_qwen`）全不可用且 `claude_subagent=false` → 退出码 3、不写文件、不静默放行。
- **降级告警**（`degraded`）：成功评审器只覆盖 1 个家族时，退出码仍为 0，但结果 JSON 带 `"degraded": "single_critic"`，`02_状态/02_正文校验记录.md` 也会追加一行降级告警——提示该轮「换一批模型对抗性重读」的设计意图打了折扣，人工复核需更谨慎。
- **分诊 + 分级 + 写修改提示词**：Claude 主 Agent。
- **改稿**：用户把修改提示词贴回云端同对话（表层修补）或新对话重生成（结构问题）。

## 正文验收流程

0. **落位门禁**（每轮云端稿到手后、跑任何检查之前）：先覆盖 `<本章>/01_模型输出/<原名>.md`，再**同步落位到 canonical path**——正文 `10_正文/…/章{C}.md`、细纲 `03_规划/…/规划_卷{V}_章{C}.md`。`audit_consistency.py` 与 `review_manuscript.py --chapter-dir` **只读 canonical path，不读 `01_模型输出/` 的原始回填**；落位前跑检查 = 审的是上一稿（本工作区已两次踩此坑）。若本轮打算弃用云端稿，则不落位、在 `_修订N.md` 文件头注明原因，循环到此为止。
1. **读**：本章正文、单章细纲、必读定稿数据（`00_开篇状态.md` / 主角档案 / 世界基本法则 / 本章道义伏笔）、本书技能配置。
2. **确定性检查**：
   - `python3 02_工具/01_小说通用工具/audit_consistency.py <小说目录> --format json` = 0 error（`LEXICON001` 等 warning 记入待处理）
   - Claude 主 Agent 过一遍 `00_通用写作规则_校验版.md` 第八章「一站式自检清单」（结构/场景/字数/钩子/引用/状态/主角人设/版权 + 本章触发的条件专项）
3. **多模型冷读**：`python3 02_工具/01_小说通用工具/review_manuscript.py --chapter-dir <本章工作区目录>`
   - 脚本读 `review.config.toml` 决定评审器池；`local_qwen = "auto"` 时先探测端点
   - 两遍：第一遍无参照（纯章内自洽），第二遍带细纲+世界法则+主角档案+禁用词表（查穿帮）
   - 输出合并发现 JSON；人类可读记录追加到 `<本章>/02_状态/02_正文校验记录.md`
   - JSON 里 `claude_subagent_requested = true` 时，主 Agent 额外 spawn 一个 general-purpose subagent：**只喂正文全文 + 冷读清单，不给它主对话上下文**（真冷读）；其发现并入
   - 脚本报「无可用独立评审器」（退出码 3）→ 上报用户，**不静默放行**
   - **细纲漏写（反向覆盖）**：冷读 pass2 清单已含此项——细纲要求的 beat/资源/伏笔埋设/钩子/动机/展示项，正文找不到落地即 `kind=漏写`。并入下一步的落地核对。
3.5. **细纲落地核对（Claude 主 Agent · 覆盖审计）**——与冷读互补：冷读找"写错的/写多的"，这步找"该写没写的"。云端模型在零上下文里重写，最爱把**动机、前因、"这是老习惯"这类连接性交代**压掉，只留鲜活的动作，冷读未必抓得到。
   - 逐场景把细纲拆成清单：`场景内容简述的关键 beat` · `涉及资源` 每项 · `涉及伏笔`（含埋设方式：发热/共鸣/异动…）· `场景钩子` 的核心张力 · `本章落地道义` · 细纲/开篇三章指南指定的展示项（底层视角细节 ×N、谨慎行为 ≥3、内心评估、主角年龄锚定、关键制度/黑话的同章行为锚点…）
   - 对每一条：在正文里指出**落地锚点句**（引 ≤12 字）或标 `❌未落地`
   - `❌` 一律计为必改项（除非用户显式 waive）
   - 结果表追加到 `<本章>/02_状态/02_正文校验记录.md`（与【一】开篇三章契约核对同体例；细纲轮的对应表在 `03_细纲对照记录.md`）
4. **分诊 + 分级**（Claude 主 Agent）：
   - 表层修补（用词/数值/单句矛盾）→ 云端「同对话」增量改
   - 结构问题（场景切分错、连续两转折、钩子失效、细纲外脑补需退回细纲层）→ 重出提示词、新对话重生成
   - **修改提示词是一份自包含云端提示词**，规格见 `00_通用模板/04_提示词/00_云端提示词生成器.md`「输出文件与预建」·冷读循环的修订轮（唯一规格来源，此处不复述）。
   - **【必读红线】段 = 整段内联本书 `01_设定/00_红线包.md` ＋ 本轮涉及的单章项**（本章 DY 的处理方式、本章伏笔号、本章场景功能与字数分配、本章有名角色名单）。**不再逐轮判断「这次该蒸馏哪几条」**——红线包已把逐章不变的那半份约束打包好（人设/古玉档位/经济锚点/文风与情绪引擎/视角纪律/禁用词/结构通则），改稿模型在零上下文新对话里除提示词外看不到任何模板，整段给它比挑着给更安全，也免掉每轮的主观取舍。
   - 红线包若与本章细纲的既定裁决冲突，**在【必读红线】段末尾单列一条「本章覆盖」**说明，不要就地改红线包正文（红线包是卷级蒸馏视图，改它要走它自己的刷新流程）。
   - **修改提示词存 `<本章>/00_提示词/01_正文生成_修订N.md`**（N=轮次）；用户贴回云端的返修稿存 `<本章>/01_模型输出/01_正文生成_修订N.md`（配对，`WS006`）。返修稿被采纳即覆盖 `01_模型输出/01_正文生成.md` 再落位到 `10_正文/…`；弃用则在 `_修订N.md` 文件头注明原因。分诊表格追加到 `02_状态/02_正文校验记录.md`。
5. **循环**：用户贴回云端改稿 → **先做步骤 0 落位** → 回到步骤 2 重跑**全套**（含 3.5 细纲落地核对；打补丁会碰坏别处、也会漏掉新压缩掉的 beat）→ **云端返修最多 2 轮**。
   - **第 3 轮起不再整篇重出**，改为「本地精修 + 人工通读」：主 Agent 直接改正文的具体句子，改完仍跑步骤 2 与 3.5。
   - 理由（ch0001 的教训，别再交一次学费）：整篇重出会碰坏别处——修订1 丢了模板结构整稿弃用；FH-067 的触发源「沟壁灼烧刻痕」前三稿全漏，到修订3 才补上。**正文层的缺陷多是随机的、重出即消失，不值得为它反复付整篇重写的风险**；系统性缺陷应该在细纲层就被拦掉（见下「细纲循环」的门禁）。
6. **门禁**：必改项（含 3.5 的 `❌未落地`）未清且用户未显式 waive → 标「待修改」，不得存档为定稿；**2 轮云端 + 本地精修后仍不干净 → 上报用户人工定**。
7. **通读发现归口分诊**（定稿前必做，**不得跳过**）——本章所有人工通读发现（含用户口头提出的），逐条判定归口，五选一并**当场落到对应文件**：

   | 归口 | 落到哪 | 判据 |
   |---|---|---|
   | 本章个案 | 只改正文，不外溢 | 换一章不会再犯 |
   | 用词穿帮 | 本书 `01_设定/00_禁用词表.md` | 下章起由 `manuscript_lexicon` 自动拦，零人工成本 |
   | 文风/质感 | 本书 `01_设定/00_文风.md` 或 `01_设定/00_红线包.md` §四 | 属"怎么写"的稳定偏好 |
   | 细纲缺口 | `00_通用模板/04_提示词/00_云端提示词生成器.md` 任务 11【任务目标】硬约束（现有 ①②③ 即 ch1 教训回写，继续追加编号） | 正文层拦不住、必须在细纲层锁死 |
   | 结构可判定 | 新增 `audit_consistency.py` 规则 | 能写成确定性检查的，就不该再靠人眼 |

   - **归口结论写进 `02_状态/02_正文校验记录.md`**，每条注明落到了哪个文件；判为「本章个案」的也要写明**为什么不外溢**。
   - 依据：ch0001 的 8 条问题里 3 条是细纲硬伤（改细纲后任何模型重出都不再犯），5 条是正文层随机瑕疵。**能外溢的发现不外溢，就等于第 50 章还在交第 1 章的学费**——这一步是本系统「每章成本递减」的唯一机制化路径。

## 细纲循环

细纲从云端落位后同样走（**先做步骤 0 落位**：覆盖 `01_模型输出/00_单章细纲.md` 并同步到 `03_规划/…/规划_卷{V}_章{C}.md`，脚本只读后者）：`review_manuscript.py --chapter-dir <本章目录> --mode outline`
- 冷读侧重：场景功能不重复、无连续两转折、单场 ≤800 同质字、出场对象清单完整（`@财务`/`@物品`/`@关系` 不漏）、数值机制细纲内闭合、既有设定与已确认决定同步
- 记录追加到 `<本章>/02_状态/03_细纲对照记录.md`
- 分诊 → 修改提示词（自包含，规格同上：【已有数据】段内联上一轮细纲全文；存 `<本章>/00_提示词/00_单章细纲_修订N.md`）→ 云端改（返修稿存 `<本章>/01_模型输出/00_单章细纲_修订N.md`，配对）→ 采纳即覆盖 `01_模型输出/00_单章细纲.md` 再落位 `03_规划/…`，弃用则文件头注明 → 重跑
- **门禁（比正文严）**：细纲的**必改项必须清零**才允许去拼正文提示词——**不接受「≤3 轮或用户 waive」**。
  - 理由：细纲只有几 KB，多跑一轮冷读极便宜；而细纲缺陷是**系统性**的，会原样复制到之后每一版正文（ch0001 的「称重 vs 计件」「手电光柱」「对古玉一头雾水」三条，三个不同模型的稿子**全部照抄**，因为细纲字面就那么写的）。**在细纲层多花一轮，胜过在正文层花四轮。**
  - 若某条必改项确实需要用户拍板才能定，标「待裁决」挂起并上报，**不得带着它进正文阶段**。

## 禁止

- 不以「写正文的模型自查一遍」替代独立冷读。
- 不以主观印象替代字段检查，不跳过条件专项项。
- 评审器全挂时不静默放行——上报用户。
- 不把阶段中间稿标为定稿。
