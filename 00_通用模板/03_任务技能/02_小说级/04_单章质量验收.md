# 单章质量验收技能

> 用户实验证明：写正文的那个模型自查会替自己找补；**换一批模型冷读、不看它的思考过程，
> 才挑得出前后矛盾/不闭合/脑补/穿帮**。本技能把「顺手自查」换成「确定性检查 + 多模型冷读循环」。

## 触发条件

用户要求单章验收、正文质检、章节检查、质量检查，或正文/细纲刚从云端落位为草稿时执行。

## 分工

- **冷读**（找问题）：评审器池——OpenCode 免费模型 ∥ 本地 Qwen（若开机） ∥ 可选 Claude subagent。由 `review_manuscript.py` 编排，见 `02_工具/00_系统级/review.config.toml`。
- **分诊 + 分级 + 写修改提示词**：Claude 主 Agent。
- **改稿**：用户把修改提示词贴回云端同对话（表层修补）或新对话重生成（结构问题）。

## 正文验收流程

0. **落位门禁**（每轮云端稿到手后、跑任何检查之前）：先覆盖 `<本章>/01_模型输出/<原名>.md`，再**同步落位到 canonical path**——正文 `10_正文/…/章{C}.md`、细纲 `03_规划/…/规划_卷{V}_章{C}.md`。`audit_consistency.py` 与 `review_manuscript.py --chapter-dir` **只读 canonical path，不读 `01_模型输出/` 的原始回填**；落位前跑检查 = 审的是上一稿（本工作区已两次踩此坑）。若本轮打算弃用云端稿，则不落位、在 `_修订N.md` 文件头注明原因，循环到此为止。
1. **读**：本章正文、单章细纲、必读定稿数据（`00_开篇状态.md` / 主角档案 / 世界基本法则 / 本章道义伏笔）、本书技能配置。
2. **确定性检查**：
   - `python3 02_工具/01_小说通用工具/audit_consistency.py <小说目录> --format json` = 0 error（`LEXICON001` 等 warning 记入待处理）
   - Claude 主 Agent 过一遍 `00_通用写作规则_校验版.md` 第八章「一站式自检清单」（结构/场景/字数/钩子/引用/状态/主角人设/版权 + 本章触发的条件专项）
3. **多模型冷读**：`python3 02_工具/01_小说通用工具/review_manuscript.py --chapter-dir <本章工作区目录>`
   - 脚本读 `review.config.toml` 决定评审器池；`local_qwen = "auto"` 时先探测端点
   - 两遍：第一遍无参照（纯章内自洽），第二遍带细纲+世界法则+主角档案+禁用词表（查穿帮）
   - 输出合并发现 JSON；人类可读记录追加到 `<本章>/02_状态/02_正文校验记录.md`
   - JSON 里 `claude_subagent_requested = true` 时，主 Agent 额外 spawn 一个 general-purpose subagent：**只喂正文全文 + 冷读清单，不给它主对话上下文**（真冷读）；其发现并入
   - 脚本报「无可用独立评审器」（退出码 3）→ 上报用户，**不静默放行**
4. **分诊 + 分级**（Claude 主 Agent）：
   - 表层修补（用词/数值/单句矛盾）→ 云端「同对话」增量改
   - 结构问题（场景切分错、连续两转折、钩子失效、细纲外脑补需退回细纲层）→ 重出提示词、新对话重生成
   - **修改提示词是一份自包含云端提示词**，规格见 `00_通用模板/04_提示词/00_云端提示词生成器.md`「输出文件与预建」·冷读循环的修订轮（唯一规格来源，此处不复述）。本技能只补一句分诊侧的取舍：【必读红线】段只挑本轮改动真正涉及的约束（开篇/古玉红线/DY-006 本章处理/经济锚点/禁用词/限知视角/有名角色数…），不要把整份红线全抄进去——但**只要本轮有"改写/新写句子"的修改项，文风与情绪引擎（反差共情/付出回报不对等/感悟依附事件/主角双重人格里层质感/爽感禁忌相关项）就算"本轮涉及的约束"，必须蒸馏进红线**（改稿模型在零上下文新对话里，除这份提示词外看不到文风模板）。
   - **修改提示词存 `<本章>/00_提示词/01_正文生成_修订N.md`**（N=轮次）；用户贴回云端的返修稿存 `<本章>/01_模型输出/01_正文生成_修订N.md`（配对，`WS006`）。返修稿被采纳即覆盖 `01_模型输出/01_正文生成.md` 再落位到 `10_正文/…`；弃用则在 `_修订N.md` 文件头注明原因。分诊表格追加到 `02_状态/02_正文校验记录.md`。
5. **循环**：用户贴回云端改稿 → **先做步骤 0 落位** → 回到步骤 2 重跑**全套**（打补丁会碰坏别处）→ 最多 3 轮
6. **门禁**：必改项未清且用户未显式 waive → 标「待修改」，不得存档为定稿；到 3 轮仍不干净 → 上报用户人工定。

## 细纲循环

细纲从云端落位后同样走（**先做步骤 0 落位**：覆盖 `01_模型输出/00_单章细纲.md` 并同步到 `03_规划/…/规划_卷{V}_章{C}.md`，脚本只读后者）：`review_manuscript.py --chapter-dir <本章目录> --mode outline`
- 冷读侧重：场景功能不重复、无连续两转折、单场 ≤800 同质字、出场对象清单完整（`@财务`/`@物品`/`@关系` 不漏）、数值机制细纲内闭合、既有设定与已确认决定同步
- 记录追加到 `<本章>/02_状态/03_细纲对照记录.md`
- 分诊 → 修改提示词（自包含，规格同上：【已有数据】段内联上一轮细纲全文；存 `<本章>/00_提示词/00_单章细纲_修订N.md`）→ 云端改（返修稿存 `<本章>/01_模型输出/00_单章细纲_修订N.md`，配对）→ 采纳即覆盖 `01_模型输出/00_单章细纲.md` 再落位 `03_规划/…`，弃用则文件头注明 → 重跑

## 禁止

- 不以「写正文的模型自查一遍」替代独立冷读。
- 不以主观印象替代字段检查，不跳过条件专项项。
- 评审器全挂时不静默放行——上报用户。
- 不把阶段中间稿标为定稿。
