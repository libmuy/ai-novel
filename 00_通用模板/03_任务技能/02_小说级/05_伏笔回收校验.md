# 伏笔回收校验技能

> **确定性的那一半已经脚本化**：`audit_consistency.py` 的 `foreshadow` / `foreshadow_schedule`
> 规则（`FS001`~`FS005`）自动查 FH 号登记、埋设逾期、回收逾期、无回收计划。
> 规则代码定义见 `01_项目状态审计.md`「伏笔登记与排期」。
> 本技能只做**脚本判不了的那一半**：回收得算不算数、够不够分量、要不要顺延。

## 触发条件

用户要求伏笔校验、伏笔回收检查或检查伏笔闭合；卷末收尾；`FS003`~`FS005` 报警。

## 流程

1. **先跑脚本**，把可判定的问题挑干净：

   ```
   python3 02_工具/01_小说通用工具/audit_consistency.py <小说目录> --rule foreshadow --format text
   python3 02_工具/01_小说通用工具/audit_consistency.py <小说目录> --rule foreshadow_schedule --format text
   ```

   - `FS003` 埋设逾期 → 要么补该章细纲的埋设动作并回改正文，要么把伏笔册的「埋设位置」
     改到实际埋设的那一章。**埋设位置写错会让后续所有回收判断都对不上**，优先修。
   - `FS004` 回收逾期 → 在该卷伏笔册「本卷拟回收/触发」表补登回收章节与执行状态；
     确定推迟就把「拟回收卷/章」改到新计划点，别让它默默逾期。
   - `FS005` 无回收计划 → 补「拟回收卷/章」。

2. **人工判定回收质量**（脚本只知道「登记了没有」，不知道「回收得好不好」）：
   - 正文里的回收动作与卷册登记的「回收触发事件」是否一致？登记了但正文没真写，等于没回收。
   - 「回收冲击类型」（逻辑 / 情感 / 世界观冲击）是否兑现？读者读到那一段有没有「原来如此」。
   - 是**完全回收**还是**阶段性回收**？阶段性回收要在执行状态里写清**还悬着什么**
     （例：「已回收（阶段性：入道机制坐实，深层来历仍悬）」），并保持总纲状态为「活跃」。
   - 跨度（卷内 / 部内 / 整书）与实际回收距离是否匹配？整书伏笔在卷 1 就收完，说明跨度定错了。

3. **总纲状态维护**：确认某 FH 彻底闭合后，把 `03_规划/00_伏笔总纲.md` 的「状态」列改为
   「已回收」。废弃的伏笔标「已废弃」，**不删行、不复用号**。

4. 输出问题清单与建议；**不直接改伏笔状态**，除非用户明确要求维护。

## 为什么这两半要分开

「总纲状态 vs 卷册执行状态」**故意没写成规则**：阶段性回收下，卷册记「已回收（阶段性…）」
而总纲记「活跃」是**正确**的，两者都对。把它做成确定性检查只会制造假阳性，
逼人去关消音开关——那比没有检查更糟。这类判断留给本技能第 2 步。

## 禁止

- 不凭正文猜造伏笔 ID；新号一律 = 总纲已用最大号 +1，并当场登记进总纲。
- 不删除未回收伏笔，不把相似情节自动判定为回收。
- 不为了让 `FS004` 归零而把「拟回收卷/章」一路往后推——那是把债往后滚，不是还债。
  推迟要有理由，写进卷册。
