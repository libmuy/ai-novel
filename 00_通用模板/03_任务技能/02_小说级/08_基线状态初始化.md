# 基线状态初始化技能

## 触发条件

`01_设定/` 与 `02_数据库/` 全部定稿之后、写第 1 章正文之前，用户要求初始化基线状态、
生成创世状态时执行。**一次性**，此后基线只读不可变。

## 前置认知

- 状态唯一权威存储是 `05_工作区/00_全局/01_最新状态/`（每对象一文件、按类目分层）。
- 冻结基线 `05_工作区/00_全局/00_基线状态/` = 第 1 章开篇前的全量对象状态，布局同上。
- `05_工作区/00_全局/01_最新状态/` == 基线 ⊕ 全部 `04_本章状态履历.md` 的折叠。基线是折叠的起点。

## 流程

1. **前置检查**：`00_进度.md` 里 `01_设定/`、`02_数据库/` 各分类均为「定稿」；
   `05_工作区/00_全局/00_基线状态/` 目前只有 `00_说明.md`（尚未初始化）。

2. **抽取起点状态**：从 `01_设定/00_主角档案.md`、`02_数据库/`（人物/势力/资源/地理）、
   `01_设定/00_小说概念.md`【世界基本法则】等定稿数据，按 `00_通用模板/03_字段词表.md`
   的官方字段表，整理出第 1 章开篇时应有的对象状态。对象 ID 用 `角色.<姓名>` /
   `物品.<名称>` / `势力.<名称>` / `财务.<对象名>` / `世界.<主体>`。

3. **写基线**：把整理结果写成 `05_工作区/00_全局/00_基线状态/` 的每对象文件
   （`NN_类目/NN_类目_<名>.md`，标准 4 列 + `> 对象ID:` 头行）。可直接用
   `state_tree.write_state_tree(baseline_dir, records, manifest=False,
   note=state_tree.BASELINE_NOTE)` 生成，保证格式与脚本一致。

4. **同步 `05_工作区/00_全局/01_最新状态/`**：把基线内容原样复制成 `05_工作区/00_全局/01_最新状态/` 的树
   （`折叠至章: __none__`），此时二者相同。（尚无任何章履历。）

5. **校验**：
   ```
   python3 02_工具/audit_consistency.py <小说目录> --format text
   ```
   必须无 `state_baseline_missing` / `global_state_unparseable` /
   `global_state_header_mismatch` / `global_state_field_illegal` /
   `global_state_misfiled` / `state_unknown_prefix`。
   数值字段的值必须是纯数字（如 `100`），否则首次 `merge` 会 `StateMergeError`。

## 禁止

- 不在设定/数据库定稿前做。
- 生成后不再改基线；剧情起点调整走 `06_章节回溯修改.md` 或改设定 + 第 1 章履历。
- 不手写 `00_同步状态.md`（由脚本维护）。
