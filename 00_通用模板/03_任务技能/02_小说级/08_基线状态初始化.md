# 基线状态初始化技能

## 触发条件

`01_设定/` 与 `02_数据库/` 全部定稿之后、写第 1 章正文之前，用户要求初始化基线状态、
生成创世状态时执行。**一次性**，此后基线只读不可变。

## 前置认知

- 状态唯一权威存储是 `05_工作区/00_全局/01_最新状态/`（每对象一文件、按类目分层）。
- 冻结基线 `05_工作区/00_全局/00_基线状态/` = 第 1 章开篇前的对象状态，布局同上。
- `05_工作区/00_全局/01_最新状态/` == 基线 ⊕ 全部 `04_本章状态履历.md` 的折叠。基线是折叠的起点。

## 基线范围规则（硬规则）

- **基线只登记第 1 章开篇时确有状态、且剧情会用到的对象**。判据：该对象在第 1 卷内会登场或被主角直接博弈。
- **不为「卡片存在但本卷不登场」的对象预建条目**。数据库里几十张人物/势力卡，绝大多数在第 1 卷之外才登场——它们只在卡片上声明「动态字段清单」，基线里没有条目。
- **新对象在其首次登场章的 `04_本章状态履历.md` 里用「新建」变更类型引入**，`build_state_snapshot.py --at-chapter` 会把它带进该章及以后的开篇状态。
- 因此 `build_baseline.py` 扫卡片动态字段清单生成的是「候选初值」，Agent 须按上述范围规则筛掉不登场对象，不是全量落盘。

## 流程

1. **前置检查**：`00_进度.md` 里 `01_设定/`、`02_数据库/` 各分类均为「定稿」；
   `05_工作区/00_全局/00_基线状态/` 目前只有 `00_说明.md`（尚未初始化）。

2. **抽取起点状态**：

   **2a. 半自动候选**：先跑
   ```
   python3 02_工具/01_小说通用工具/build_baseline.py <小说目录>
   ```
   它扫全部人物卡 + 主角档案 + 势力卡的「## 动态字段清单」已填初值，生成候选树到
   `05_工作区/00_全局/00_基线候选/`，并报告：哪些字段初值待你确认、哪些卡缺清单。
   **候选 ≠ 基线**——它是全量的，下一步要按【基线范围规则】筛。

   **2b. 人工整理**：以候选为起点，从 `01_设定/00_主角档案.md`、`02_数据库/`（人物/势力/资源/地理）、
   `01_设定/00_小说概念.md`【世界基本法则】等定稿数据，按 `00_通用模板/03_字段词表.md`
   的官方字段表，整理出第 1 章开篇时应有的对象状态。对象 ID 用 `角色.<姓名>` /
   `物品.<名称>` / `势力.<名称>` / `财务.<对象名>` / `世界.<主体>`。
   - 物品 / 财务 / 世界对象**不在候选里**（那些卡没有动态字段清单）——主角随身物品
     （矿钉 / 骨针 / 异宝等）按主角档案说明建为 `物品.<名称>`、`持有者 = @主角`。
   - 群像 / 临时 / 背景对象若确需进状态、又不该建卡，登记到
     `05_工作区/00_全局/00_状态对象白名单.md`（audit `state_object_unregistered` 据此放行）。

   - **势力的「与主角互动状态」**：首次进入状态时从官方枚举（`中立` / `敌对` / `友好` / `隐秘关注`）里选一个，
     不照抄势力卡「与主角关系·当前状态」里的自由描述（「利用」「未知」「中立偏敌对」「复杂」等）；
     卡片描述的多是全书弧线里某个阶段的关系，不是第 1 章此刻的关系。
   - **物品归属**只写 `物品.Y 的「持有者」`；不写 `持有物品`（已废除）。
   - **对称关系对象** `关系.<甲>&<乙>`：只有第 1 章开篇就是既定事实、且卷 1 内影响剧情决策的
     对称关系（母子/血亲/结盟/宿怨…）才进基线。两端名字按 Unicode 码位排序、ASCII `&` 拼接；
     两端必须都是已建卡对象。字段见 `03_字段词表.md` 第 6 节。到某章才「落到纸面」的关系
     （如主角与压迫者的敌对，往往第 1 章某个场景才成立）走该章履历「新建」，不进基线。
   - **不确定某字段的初值时留空并报给用户，不要编**——这是内容创作职责边界（灵石数、所在地、亲疏档位等）。

3. **写基线**：把整理结果写成 `05_工作区/00_全局/00_基线状态/` 的每对象文件
   （`NN_类目/NN_类目_<名>.md`，标准 4 列 + `> 对象ID:` 头行）。可直接用
   `state_tree.write_state_tree(baseline_dir, records, manifest=False,
   note=state_tree.BASELINE_NOTE)` 生成，保证格式与脚本一致。

4. **同步 `05_工作区/00_全局/01_最新状态/`**：把基线内容原样复制成 `05_工作区/00_全局/01_最新状态/` 的树
   （`折叠至章: __none__`），此时二者相同。（尚无任何章履历。）

5. **删候选**：筛选完成后删掉 `05_工作区/00_全局/00_基线候选/`（它是暂存区，不进版本库长期留存）。

6. **校验**：
   ```
   python3 02_工具/01_小说通用工具/audit_consistency.py <小说目录> --format text
   ```
   必须无 `state_baseline_missing` / `global_state_unparseable` /
   `global_state_header_mismatch` / `global_state_field_illegal` /
   `global_state_misfiled` / `state_unknown_prefix` /
   `state_object_unregistered` / `state_field_undeclared` / `RELATION001`。
   数值字段的值必须是纯数字（如 `100`），否则首次 `merge` 会 `StateMergeError`。

## 禁止

- 不在设定/数据库定稿前做。
- 生成后不再改基线；剧情起点调整走 `06_章节回溯修改.md` 或改设定 + 第 1 章履历。
- 不手写 `00_同步状态.md`（由脚本维护）。
