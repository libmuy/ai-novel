# 提示词拼装技能

> **本技能只写「怎么执行」。** 提示词该长什么样（六段骨架 / 预建 / 存档命名 / 规则引用纪律 /
> 示例去污染 / 修订轮）的唯一规格来源是 `00_通用模板/04_提示词/00_云端提示词生成器.md`，
> 正文阶段的任务指令在 `00_通用模板/01_写作规则/01_系统指令.md`。此处只引用、不复述。

## 触发条件

要为某章拼装云端提示词（单章细纲 / 正文），或问「下一章该发什么给云端」。

## 为什么改成脚本

ch0001 → ch0002 的数据：冷读轮次 28 → 10 个 commit、校验记录 85 → 36 KB，
**质量循环在自己变便宜**；但基础两份提示词 91 → 141 KB，**涨了 55%**。
循环会学习，手工拼装不会——每章都是从零手抄一遍模板与卡片。
而且手抄顺带做「本章适用部分节录」，压缩口径逐章漂移，规格里明明写的是**全文内联**。

已经为此付过的学费：内部标识泄漏进正文（ch0002 修订1「章0001 买的止咳散」）、
产出存名存错、旧提示词内联数据过期。每一条的补丁都是「再加一条规则让 Agent 记得」——
能写成确定性检查的，就不该再靠人记得。

## 用法

```
python3 02_工具/01_小说通用工具/build_prompt.py --novel <小说目录> --task 细纲 --chapter 3
python3 02_工具/01_小说通用工具/build_prompt.py --novel <小说目录> --task 正文 --chapter 3
python3 02_工具/01_小说通用工具/build_prompt.py --chapter-dir <章工作区目录> --task 正文
```

参数与退出码以 `--help` 为准。要点：

- **`--dry-run` 先看一眼**：报告体量、待人工确认项、泄漏自检结果、准备阶段将做什么，不写任何文件、不调 LLM（只探测端点连通性）。
- **默认不覆盖已有存档**。提示词是可重新生成的执行缓存，数据变了就该重拼——确认要重拼时加 `--force`。
- 退出码：`0` 已生成 ／ `2` 前置门禁或准备阶段未过（只出阻断报告，**一个文件都没写**）／ `3` 生成了但自检有发现，需人工过一遍。

### 四段流程

| 阶段 | 干什么 | 失败后果 |
|---|---|---|
| GATE | 只查 `00_进度.md` 里必读前置是否「定稿」 | 阻断报告 + 退出 2，一个文件都不写 |
| PREPARE | 物化派生输入：**开篇状态**（确定性折叠 `build_state_snapshot.py --chapter-opener`）＋**上章摘要**（LLM 压缩，细纲任务、非首章） | 阻断报告 + 退出 2，不写存档 / 不预建 |
| ASSEMBLE | 纯读：模板 + 定稿数据 + 已物化的派生输入 → 提示词文本 | — |
| EMIT | 写提示词存档、预建回填 / 目标空文件 | — |

`--dry-run` 只跑 GATE + 报告 PREPARE 计划，不执行 PREPARE、不写、不调 LLM。

## 流程

1. **跑 `--dry-run`**。GATE 不过就照阻断报告去补前置，不要想办法绕过去；
   PREPARE 计划里若提示「端点不可达且未装 opencode」，正式跑会被摘要生成阻断，先把 LLM 通路弄通。
2. **看「待人工确认」**：脚本对需要作者判断的地方（卷纲缺本章节拍…）
   只留 `>>>` 标记，**不代笔**。逐条补完再发云端。
3. **看泄漏自检**：脚本只对自己撰写的叙事指令段落做检查。有发现就按提示改，别放行。
4. **正式生成**（去掉 `--dry-run`），脚本同时预建回填空文件与目标数据文件。
5. **人工通读一遍提示词**再发云端——脚本保证结构与取材正确，不保证这一章该这么写。
   细纲提示词尤其要核这几处脚本抓不到的缺口，有问题就**自己补进【任务目标】的"待确认清单"**
   （别指望云端规划师发现）：
   - **上章钩子是否落地**：上一章章末钩子（尤其重钩）留下的危机，本章【已有数据】A 的节拍
     摘要有没有交代怎么收？没有的话，摘要与"不得多出摘要之外的主线事件"这条自检会打架，
     规划师会把钩子糊掉——补一句"本章开场须先化解上章 XX 危机"。
   - **本章特有的钱/数量**：赠予、缴获、克扣、消耗涉及的资源，源数字（多少下品、什么档位）
     在内联的卷大纲资源子表或资源卡里查得到吗？查不到就补。
   - **突破/晋升章**：冲突原型要对应的【破境考验】，内联的体系卡里那一格是不是"—"？
     是的话提醒规划师别硬凑体系外考验。
6. 云端产出回来后走技能 `04_单章质量验收.md`：**先落位**，再跑 `review_manuscript.py` 冷读循环。

## PREPARE 阶段：两类派生输入

准备阶段在 GATE 通过后、`--dry-run` 之外执行，物化两样提示词需要、但不是作者手写的输入。

### 开篇状态（确定性，不调 LLM）

`00_开篇状态.md` = 冻结基线 ⊕ 折叠「排序严格早于本章」的全部章履历，再按本章细纲
「## 出场对象」裁剪（细纲任务时细纲还没产出 → 写全量）。纯 Python 折叠，秒级。
描述类字段的跨章合并**在上一章跑 `merge_chapter_state.py` 时就做完并缓存了**，这里只做值拷贝。

- 折叠范围内有未合并的描述字段（前序某章没跑 merge）→ **退出 2 阻断**，报告点名那些章，去补 merge 再重拼。
- 冻结基线尚未初始化 → 退出 2 阻断。
- blast radius 限于本章：用 `--chapter-opener <章目录>`，不是全书扫。

### 上章摘要（需要 LLM）

把上一章整章正文压成 ≤300 字的衔接摘要——这是生成性任务，没有确定性算法。

- `00_提示词/上章摘要.md` 已存在且不是 `>>>` 占位 → 直接复用（不重新生成，`--force` 也不冲掉）。
- 缺失 → 调 `_llm.summarize_chapter`（`backend=auto`：本地端点优先，不可达降级 opencode），
  写入文件（纯正文、无标记）。拼装报告里写「已由 LLM 生成——发云端前请自行复核衔接」。
- **LLM 完全不可用（端点不可达 且 未装 opencode）→ 退出 2 阻断**，不写占位、不放行带洞的提示词。
  逃生口：手写该文件后重拼即直接采用。

**复核由作者在发云端前做**：LLM 压出来的摘要没人核过，对一下上一章正文结尾一致不一致、
有没有丢关键局势；不留文件内标记——复核完直接让 Agent 往下走。要改就改摘要文件、重拼即带入。

## 脚本保证什么、不保证什么

| 保证 | 不保证 |
|---|---|
| 六段骨架齐全、区块顺序固定 | 这一章的剧情设计是否成立 |
| 规则件与卡片**全文逐字内联**，不做有损节录 | 上章摘要的质量（LLM 生成，作者发云端前自行复核） |
| 开篇状态确定性物化，前序脏账就阻断 | 细纲本身的出场对象表是否写全 |
| 上章摘要缺失就调 LLM 生成；LLM 全断则阻断 | `00_进度.md` 的成熟度标注是否属实 |
| 出场卡片按细纲「## 出场对象」表逐个解析，不漏不多 | 逐字内联的源文件里的编号（那是源文件的事） |
| GATE / PREPARE 不过就阻断，不生成半成品、不预建 | 云端模型会不会照办 |
| 自己撰写的段落不含仓库内部标识 | |
| 存档 / 回填 / 目标三类文件按规格预建、只创建不覆盖 | |

## 禁止

- 不手工拼装提示词绕过脚本——手抄正是这套工具要消灭的成本。
- 不在脚本里写小说内容。脚本只做「取材 + 排版」，凡需要作者判断的一律留 `>>>` 标记。
- 门禁不过时不得改 `00_进度.md` 的成熟度来放行；那是伪造前置。
- 规格变化时改 `00_云端提示词生成器.md` / `01_系统指令.md`，**再**回来改脚本；不得反过来让脚本成为事实规格。
- LLM 不可用时不得跳过摘要生成、放行带 `>>>` 的提示词——必须退出 2 阻断。想手写摘要就手写文件本身，别让脚本发半成品。
- 不给 LLM 生成的摘要加文件内标记——复核是作者发云端前的一步，不进 `>>>`、不进冷读门禁。
- PREPARE 的开篇状态物化不得放到 GATE 之前，也不得在 `--dry-run` 下执行——`--dry-run` 零副作用是这套流程的前提。
