# 提示词拼装技能

> **本技能只写「怎么执行」。** 提示词该长什么样（六段骨架 / 预建 / 存档命名 / 规则引用纪律 /
> 示例去污染 / 修订轮）的唯一规格来源是 `00_通用模板/04_提示词/00_云端提示词生成器.md`，
> 正文阶段的任务指令在 `00_通用模板/01_写作规则/01_系统指令.md`。此处只引用、不复述。

## 触发条件

要为某章拼装云端提示词（单章细纲 / 正文），或问「下一章该发什么给云端」。

## 为什么改成脚本

ch0001 → ch0002 的数据：冷读轮次 28 → 10 个 commit、校验记录 85 → 36 KB，
**质量循环在自己变便宜**；但基础两份提示词 91 → 141 KB，**涨了 55%**。
循环会学习，手工拼装不会——每章都是从零手抄一遍模板与卡片。
而且手抄顺带做「本章适用部分节录」，压缩口径逐章漂移，规格里明明写的是**全文内联**。

已经为此付过的学费：内部标识泄漏进正文（ch0002 修订1「章0001 买的止咳散」）、
产出存名存错、旧提示词内联数据过期。每一条的补丁都是「再加一条规则让 Agent 记得」——
能写成确定性检查的，就不该再靠人记得。

## 用法

```
python3 02_工具/01_小说通用工具/build_prompt.py --novel <小说目录> --task 细纲 --chapter 3
python3 02_工具/01_小说通用工具/build_prompt.py --novel <小说目录> --task 正文 --chapter 3
python3 02_工具/01_小说通用工具/build_prompt.py --chapter-dir <章工作区目录> --task 正文
```

参数与退出码以 `--help` 为准。要点：

- **`--dry-run` 先看一眼**：报告体量、待人工确认项、泄漏自检结果，不写任何文件。
- **默认不覆盖已有存档**。提示词是可重新生成的执行缓存，数据变了就该重拼——确认要重拼时加 `--force`。
- 退出码：`0` 已生成 ／ `2` 前置门禁未过（只出阻断报告，**一个文件都没写**）／ `3` 生成了但自检有发现，需人工过一遍。

## 流程

1. **跑 `--dry-run`**。门禁不过就照阻断报告去补前置，不要想办法绕过去。
2. **看「待人工确认」**：脚本对需要作者判断的地方（上章 300 字摘要、卷纲缺本章节拍…）
   只留 `>>>` 标记，**不代笔**。逐条补完再发云端。
3. **看泄漏自检**：脚本只对自己撰写的叙事指令段落做检查。有发现就按提示改，别放行。
4. **正式生成**（去掉 `--dry-run`），脚本同时预建回填空文件与目标数据文件。
5. **人工通读一遍提示词**再发云端——脚本保证结构与取材正确，不保证这一章该这么写。
6. 云端产出回来后走技能 `04_单章质量验收.md`：**先落位**，再跑 `review_manuscript.py` 冷读循环。

## 脚本保证什么、不保证什么

| 保证 | 不保证 |
|---|---|
| 六段骨架齐全、区块顺序固定 | 这一章的剧情设计是否成立 |
| 规则件与卡片**全文逐字内联**，不做有损节录 | 上章摘要这类需要理解性压缩的内容（留 `>>>` 待人工） |
| 出场卡片按细纲「## 出场对象」表逐个解析，不漏不多 | 细纲本身的出场对象表是否写全 |
| 前置未定稿就阻断，不生成半成品 | `00_进度.md` 的成熟度标注是否属实 |
| 自己撰写的段落不含仓库内部标识 | 逐字内联的源文件里的编号（那是源文件的事） |
| 存档 / 回填 / 目标三类文件按规格预建、只创建不覆盖 | 云端模型会不会照办 |

## 禁止

- 不手工拼装提示词绕过脚本——手抄正是这套工具要消灭的成本。
- 不在脚本里写小说内容。脚本只做「取材 + 排版」，凡需要作者判断的一律留 `>>>` 标记。
- 门禁不过时不得改 `00_进度.md` 的成熟度来放行；那是伪造前置。
- 规格变化时改 `00_云端提示词生成器.md` / `01_系统指令.md`，**再**回来改脚本；不得反过来让脚本成为事实规格。
