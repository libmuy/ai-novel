# 章节状态对账技能

## 触发条件

每章完成后，或用户要求状态对账、章后维护、更新状态时执行。

## 流程

1. 读取本章正文、事件卡、资源物品卡，以及 `04_全局状态/` 中本章出场对象的对象文件。
2. 提取伤势、消耗、战利品、突破、关系、所在地、持有和财务变化。
3. 写本章 `05_工作区/《部》/《卷》/《章》/04_本章状态履历.md`（7 列：前 4 列权威 +
   章节号/变更时间/变更类型）。语法：运算-数值 `+N/-N`、运算-列表 `+X,-Y`、
   运算-枚举写目标值、描述写自由文本。字段名与类型以 `00_通用模板/03_字段词表.md` 为准。
4. 对照正文复核事件卡；冲突以正文为准并修正事件卡与履历。
5. 把本章履历折叠进唯一权威状态存储 `04_全局状态/`：
   ```
   python3 02_工具/merge_chapter_state.py --chapter-dir <本章目录>
   ```
   - 本章若改动了「描述」类字段（旧值非空且有实质变更），脚本会调**一次** LLM 把
     旧描述 + 新描述合并成不丢信息的一段，写回 `04_全局状态/` 并冻结回写本章履历
     （「变更类型」列变 `描述合并`）。需 `02_工具/llm.config.toml` + key（环境变量或
     `02_工具/llm.secret.toml`）。**LLM 不可用且本章有描述变更 → 合并中止、退出码 2、
     不写任何文件**；纯运算章节无需 key。
   - 先 `--dry-run` 可预览合并文本与 diff。
6. 复查：`python3 02_工具/audit_consistency.py <小说目录> --format text`
   （关注 `state_drift` / `cascade_*` / `*_type_mismatch`）。
7. 输出新增变更数、`04_全局状态/` diff、漏记检查。

> 若本次改的是**已定稿的早期章节**（而非最新章），改用 `06_章节回溯修改.md`。

## 禁止

不把身份设定写入动态状态表；不手工编辑 `04_全局状态/` 与 `00_基线状态/`；
不修改历史履历记录（除非走回溯修改技能）；不跳过事件卡与正文对账。
