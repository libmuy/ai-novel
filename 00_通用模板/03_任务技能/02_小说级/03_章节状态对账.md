# 章节状态对账技能

## 触发条件

每章完成后，或用户要求状态对账、章后维护、更新状态时执行。

## 流程

1. 读取本章正文、事件卡、资源物品卡，以及 `05_工作区/02_状态/01_最新状态/` 中本章出场对象的对象文件。
2. 提取伤势、消耗、战利品、突破、关系、所在地、持有和财务变化。
   - **只追踪正文明写"角色带在身上/留存下来"的物品**。用过即弃、当场消耗、别人放下但正文
     没写主角拿走的东西，一律不建 `物品.X` 状态对象——在履历文末「本章已在正文体现、无需
     进状态的变化」段记一句即可（如「获得灵心草≈5下品→当场全数嚼服于突破，不留存」）。
     细纲【自检确认】/【出场对象】表明确说"不入表"的资源，**以细纲为准**。
   - **突破章**：主角境界变化用 `角色.<主角> 的「境界」`（运算-枚举，值＝`<体系>·<大境界>·<阶>`，
     见 `03_字段词表.md`），**不要自造「修炼状态」这类字段名**；突破留下的持久代价
     （神魂眩晕未退 / 经脉隐伤 / 虚弱期 / 功法反噬风险）写进 `隐患·未解代价`，不要只塞进
     `身体状况` 就算完。
3. 写本章 `05_工作区/《部》/《卷》/《章》/02_状态/01_状态履历.md`（7 列：前 4 列权威 +
   章节号/变更时间/变更类型）。语法：运算-数值 `+N/-N`、运算-列表 `+X,-Y`、
   运算-枚举写目标值、描述写自由文本。字段名与类型以 `00_通用模板/03_字段词表.md` 为准。
   - **物品易主**只写 `物品.Y 的「持有者」`（运算-枚举，值 `@角色.[X]` / `无人`）；
     不再写 `角色.X 的「持有物品」`（已废除）——「某人有哪些物品」由脚本反查派生。
   - **对称关系变化**（新结怨/结盟/亲疏升降/关系了断）写关系对象 `关系.<甲>&<乙>`
     （对象 ID 前缀 `关系.`、ASCII `&` 拼接）。**两端顺序按 Unicode 码位排序，别肉眼估 CJK**——
     不确定就跑 `python3 -c "import sys;sys.path.insert(0,'02_工具/00_系统级');import state_tree;print(state_tree.normalize_relation_id('关系.甲&乙'))"`。
     排在前的是「甲」，`甲对乙态度`/`乙对甲态度` 字段的视角要跟着对：`甲对乙` ＝ 排序在前者看排序在后者。
     字段见 `03_字段词表.md` 第 6 节。关系首次出现用「新建」，一端死亡/退场时补
     `关系.甲&乙 的「对象终态」= 终结`。
     （第 5 步 `merge_chapter_state.py` 折叠前会 `validate_changelog` 把关：关系ID 排序错 /
     字段名没登记 → 直接拦下、不折叠。照报错改履历再重跑。）
   - 非对称关系（师承、势力隶属）分别写 `角色.X 的「师承」` / `势力.X 的「隶属」`。
4. 对照正文复核事件卡；冲突以正文为准并修正事件卡与履历。
5. 把本章履历折叠进唯一权威状态存储 `05_工作区/02_状态/01_最新状态/`：
   ```
   python3 02_工具/01_小说通用工具/merge_chapter_state.py --chapter-dir <本章目录>
   ```
   - 本章若改动了「描述」类字段（旧值非空且有实质变更），脚本会调**一次** LLM 把
     旧描述 + 新描述合并成不丢信息的一段，写回 `05_工作区/02_状态/01_最新状态/` 并追加进
     独立的 append-only 缓存 `05_工作区/02_状态/04_描述合并缓存.jsonl`。**本章履历原文
     不会被改写**。需 `02_工具/00_系统级/llm.config.toml` + key（环境变量或 `02_工具/00_系统级/llm.secret.toml`）。
     **LLM 不可用且本章有描述变更 → 合并中止、退出码 2、不写任何文件**；纯运算章节无需 key。
   - 先 `--dry-run` 可预览合并文本与 diff（只读，不占写锁）。
   - **写锁（W6.2）**：非 dry-run 模式会独占 `05_工作区/02_状态/`。另一个进程正在写时
     直接退出码 3、**不写任何文件**——同时写会让后写的整棵树盖掉先写的，且 prune 会删掉
     对方刚建的对象文件，是静默的状态丢失。上次运行被 Ctrl-C 留下的残锁会自动接管并打印提示。
6. 复查：`python3 02_工具/01_小说通用工具/audit_consistency.py <小说目录> --format text`
   （关注 `state_drift` / `cascade_*` / `*_type_mismatch` / `RELATION001` / `RELATION002`）。
7. 刷新进度派生视图：`python3 02_工具/01_小说通用工具/progress_report.py <小说目录> --write`
   （折叠进度变了，`05_工作区/02_状态/05_进度派生视图.md` 就该重出；顺带做一次
   `00_进度.md` 对账。成熟度仍由人在 `00_进度.md` 里改，脚本不碰）。
8. 输出新增变更数、`05_工作区/02_状态/01_最新状态/` diff、漏记检查。派生视图
   `00_持有物品反查.md`、`06_关系/` 索引、`05_进度派生视图.md` 由脚本自动刷新，勿手改。

> 若本次改的是**已定稿的早期章节**（而非最新章），改用 `06_章节回溯修改.md`。

## 禁止

不把身份设定写入动态状态表；不手工编辑 `05_工作区/02_状态/01_最新状态/` 与 `00_基线状态/`；
不修改历史履历记录（除非走回溯修改技能）；不跳过事件卡与正文对账。
