# 云端提示词生成器

> 多小说共用，只读。根据当前最新定稿数据生成自包含云端提示词，存入对应小说 `05_工作区/00_提示词/` 作为执行缓存；数据或前置状态变化后必须重拼装。
>
> 与 `00_通用模板/00_使用说明.md` 的关系：任务路由见本文件「规划任务路由表」；写单章等正文阶段的任务拼装，遵循 `00_通用模板/01_写作规则/01_系统指令.md` 的任务专用指令。

---

## 职责

根据小说名和任务编号，拼装一份自包含提示词。云端不会访问仓库，因此模板、定稿数据和任务要求必须内联；本地 Agent 只拼装，不生成设定。

## 固定骨架（六段，不改结构）

每个云端提示词固定为以下六段结构，拼装时逐段填充：

```
【你的角色】规划师/设定师，严格按给定模板与数据行事，禁止凭空编造；任务开始先以多轮问答引导用户补齐必要信息，信息齐备后再生成产出，禁止在信息缺失时凭空编造；禁止照抄模板示例名称，按《{{小说名}}》题材与核心定位自主原创（指令全文见「示例去污染规则」）
【必读模板】……（本任务相关卡片模板/写作规则全文，以模板文件名为区块标题内联）
【已有数据】……（本小说已定稿数据，保证一致性）
【任务目标】生成 XX → 对应 01_设定/、02_数据库/ 或 03_规划/（若为任务00，先多轮引导采集概念信息，未齐备不生成）
【输出格式】严格按上文【必读模板】段内联模板的字段 + @引用/ID 规范；冲突以【已有数据】段为准
【验收自检】字段齐全 / @引用可解析 / 版权道义红线 / 数值符合资源 / 世界硬规则一致性（涉及世界观/修炼体系/能力/事件的产出不违反 `00_小说概念`【世界基本法则】硬规则）
```

## 规则引用纪律（防复述过期）

【任务目标】【输出格式】【验收自检】中，凡涉及某个上游数据文件（如 05_核心道义、04_资源等）的具体规则、数值、表格或字段名称时，只允许写"参照【已有数据】中 XX 文件当前内容执行"，禁止用自然语言把规则内容再复述、转译或概括一遍写进任务指令段。

规则的唯一权威文本只存在于【已有数据】区块内镜像的原文中；任务指令段引用某个表格/字段名称前，必须先确认该名称在本次【已有数据】区块实际内联的内容中确实存在，否则禁止引用。

## 生成流程

1. 查任务路由，读取 `00_进度.md`；前置数据非「定稿」则只输出阻断报告。
2. 完整内联必读模板和定稿数据；模板最多 4 个，查表数据按需读取。
3. 写入任务参数、硬性格式、输出路径和“执行前需重拼装”提示；任务 00 保留多轮采集规则（两阶段：概念信息 → 世界基本法则，未确定项标「未知」、候选方案标注「候选设计非已定」、未齐备不生成）；【你的角色】段追加「示例去污染规则」中的原创发散指令并替换 `{{小说名}}`；内联模板/规则中的具体名称示例按该规则替换为括号占位符。
3.5 规则性文字重推导：拼装或重拼装【任务目标】【输出格式】【验收自检】时，凡涉及具体规则、数值配额、字段名或表格名称的表述，必须对照 00_系统架构规范.md 与本任务对应上游数据文件的当前内容重新推导，禁止直接沿用本提示词文件历史版本的既有文字。
4. **存档提示词 + 预建两类空文件**（规则见下「输出文件与预建」）：① 提示词存档到对应作用域的 `00_提示词/<存档名>`（全书级 `05_工作区/00_提示词/`，卷/章级见「输出文件与预建」）；② 路由表「输出路径」的目标数据文件；③ **本次云端产出的回填空文件**——与存档同名，落在同级 `01_模型输出/`。全部**只创建、不覆盖**（已存在则跳过）。
5. 按「验收自检」检查。

## 输出文件与预建（所有云端提示词通用，含正文阶段）

拼装任意云端提示词时，除提示词存档文件外，**必须预建本次云端产出的回填空文件**——云端不访问仓库，产出回来后要有确定的落脚点，且提前建好空文件可避免用户手工新建时路径 / 命名跑偏。

| 文件 | 路径 | 命名 | 覆盖策略 |
|---|---|---|---|
| 提示词存档 | 按任务作用域（见路由表下方说明）：全书级任务 `05_工作区/00_提示词/`；卷级任务 `05_工作区/《部》/《卷》/00_提示词/`；章级（含正文、事件卡）`05_工作区/《部》/《卷》/《章》/00_提示词/` | 见路由表「存档文件」列（`NN_<任务名>.md`，不带"提示"后缀；正文 `01_正文生成.md`、事件卡 `02_<事件>卡.md`） | 只创建、不覆盖 |
| **云端产出回填** | 与提示词存档同级的 `01_模型输出/`（全书 `05_工作区/01_模型输出/`；卷 `…/《卷》/01_模型输出/`；章 `…/《章》/01_模型输出/`） | **与「存档文件」同名**（例：存档 `03_地理区域.md` → 回填 `03_地理区域.md`；章级 `00_单章细纲.md` → `00_单章细纲.md`） | 只创建、不覆盖 |
| 目标数据文件 | 路由表「输出路径」列（规划任务）；`10_正文/《部》/《卷》/章XXXX.md`（正文）；`03_规划/《部》/《卷》/01_事件/`（事件卡） | 见对应列 | 只创建、不覆盖 |

- 提示词的 `> 执行方式` 存档头**必须写明**该回填文件的完整路径，并说明「回填后由本地 Agent 落位到 <目标文件> + （正文阶段）据【待登记清单】回填 `02_状态/01_状态履历.md`」。
- 「合并单文件输出模式」（任务 01~05、08）的回填文件同样落在同级 `01_模型输出/`，命名与存档同名。
- 回填空文件内容：仅一行 `> 待云端产出回填（<提示词存档名>）。`
- **冷读循环的修订轮**（细纲/正文落位后走 `review_manuscript.py`，见技能 `03_任务技能/02_小说级/04_单章质量验收.md`）——**本条是修订轮提示词的唯一规格来源，他处只引用、不复述**：主 Agent 分诊产出的「修改提示词」**就是一份自包含云端提示词**，六段骨架照拼，只是两段有固定内容——【已有数据】段 = 上一轮该稿（细纲或正文）全文逐字内联；【任务】段 = 逐条外科手术式修改项（「第 X 段『…』：现状 A，问题 B，改 C 方向；留白处不许脑补，不得引入细纲外新道具/机制」）。**发给任何模型 / 任何对话都能独立执行**，不得做成引用"上一稿"却不内联的裸 diff（免费额度用光换模型时尤其致命）。存 `00_提示词/<原存档名>_修订N.md`，返修产出存 `01_模型输出/<原存档名>_修订N.md`，一一配对（`WS006`）。返修稿被采纳即覆盖 `01_模型输出/<原存档名>.md` 再落位；弃用则在 `_修订N.md` 文件头注明原因。修订提示词不进 `02_状态/`。

## 增量追加规则（父文档索引同步）

> 默认全量生成；用户明确新增/追加子条目且已有索引和子文件为定稿时，切换为增量追加。

增量任务必须：
1. 在【任务目标】注明“增量追加，非全量重建”及对象名。
2. 在【输出格式】写明：
   - **父索引追加**：在对应总索引（或上一级文件）索引表中**追加**新条目行（名称｜一句话概况｜文件链接），与既有行合并，不得覆盖或重排既有内容；
   - **逐级补链**：多级结构（地理区域「世界→区域→地名」）新增中间/底层条目时，须自顶向下逐级补齐父文件索引（世界索引/地名索引），各级索引与子文件一一对应；
   - **子文件落位**：新增子文件按各模板「文件命名规则」命名；既有子文件仅追加本条目内容，不整体重写；
   - **引用闭合**：新增条目的 `@引用` 同步登记；引用对象未成卡时按「实体创建规范（分阶段）」处理——任务 01~04 以 `@类型.[TODO-序号]` 占位符登记「待创建条目」（需求描述不含专名，禁止自创具体名称），任务 05~11 默认当场创建实体并附随文新设实体卡片、仅前向/承重对象登记 TODO。
3. 在【验收自检】增加“父索引已追加、逐级补链、既有内容未覆盖”。

生成步骤第 4 步的预建空文件（提示词存档 + 云端产出回填 + 目标数据文件）同样适用于增量追加：仅当文件不存在时预建，既有文件一律跳过（不覆盖）。

## 合并单文件输出模式（任务 01~04、08 可选）

> 用途：当用户要求"云端输出合并为一个文件 / 单文件下载"时启用，适用于任务 01~05、08（多文件拆分类：修炼体系、地理区域、势力组织、资源、书籍库；任务05主角与核心配角产出两个文件）。单文件任务（00、06~07、09~11）产出本为一个文件，不启用本模式。**粒度：每个任务一次合并**——一次云端执行的全部产出（总索引 + 全部子文件）写入**同一个 Markdown 文件**整体输出；用户把该文件保存到该任务作用域的 `01_模型输出/<回填名>`（与提示词存档同名），由本地 Agent 按 `00_通用模板/01_写作规则/07_云端回填分割规则.md` 分割回填到路由表「输出路径」对应数据文件。

拼装要求：
1. 【输出格式】在任务既有硬性要求外追加以下规则（内联模板字段本身不改动）：
   - 全部产出写入**单个 Markdown 文档**，整体输出、禁止拆成多个代码块；区块外只允许一个文件头说明段（文件名、任务名），不写汇总/目录；
   - 每个目标文件一个区块：区块开头独占一行 `<!-- FILE: <相对小说数据目录的输出路径> -->`，区块内容即该目标文件的**完整内容**（含文件内标题与区块标题），区块结束独占一行 `<!-- /FILE -->`；
   - 区块顺序与路由表「输出路径」列一致、按拆分粒度自顶向下组织：总索引区块在前，子文件区块依次在后（如任务02地理区域：总索引 → 各世界 → 各区域 → 各地名逐级）；
   - 内联模板中「产出合计 >1KB 时拆分为多文件」的规则在合并模式下不再要求云端物理拆分：区块粒度即拆分粒度，云端仅按层级组织区块，落位由本地 Agent 完成。
2. 【验收自检】在任务既有检查项外追加：
   - 每个 `<!-- FILE: -->` 路径与任务输出路径清单**精确一致**：无遗漏、无多余、无拼写偏差；
   - 区块闭合完整（`<!-- /FILE -->` 数量 = `<!-- FILE: -->` 数量，且顺序配对）；
   - 区块内字段齐全/@引用可解析/父索引同步等检查项与全量模式相同。
3. 存档文件名、预建空文件、路由表「输出路径」均**保持不变**；"一任务一文件"指提示词存档文件，与云端产出合并为单文件不冲突。预建空文件按生成步骤第 4 步「输出文件与预建」执行（回填空文件与存档同名，落在同级 `01_模型输出/`）。
4. 存档文件头（`> 执行方式` 处）注明："本提示词为**合并单文件输出模式**：云端整体输出一个 Markdown 文件；保存到同级 `01_模型输出/<存档同名>` 后由本地 Agent 分割回填。"

3. **【输出格式】段追加约束**：“模板示例仅为格式示范、非预设设定，禁止照抄示例名称；@引用 名称须与已定稿数据一致，对象不存在时按「实体创建规范（分阶段）」执行：任务 01~04 一律以 `@类型.[TODO-序号]` 占位符登记「待创建条目」；任务 05~11 及正文阶段默认当场创建实体并提供随文新设实体卡片，仅对『登场在更晚部/卷的前向对象』或『宜由专属任务设计的承重对象』登记前向引用 TODO（须填「预计引入卷」）”。
4. **ID 编号示例保留**：`V1-C03-001`、`DY-001` 等仅演示编号格式，不构成预设设定，原样保留。
5. **正文阶段适用**：按 `00_通用模板/01_写作规则/01_系统指令.md` 拼装正文阶段云端提示词时，同样执行本规则。

## 实体创建规范（分阶段）

规划阶段云端提示词拼装时，必须根据任务阶段选择对应的实体创建规范，并在【验收自检】对应检查。

> **总原则**：判据不是"第几号任务"，而是"引用对象是否落在当前任务的设计职责与时间视界之内"。落在职责/近场视界内 → 当场创建；属于更晚部/卷或专属任务领域 → 登记 TODO。

### 早期阶段规范（任务 01~04）

任务 01~04（修炼体系、资源、地理区域、势力组织）执行时，由于数据库尚未完全建立，缺失的下游领域对象一律使用 TODO 占位符：

> **早期阶段占位符规范**
>
> 1. **正文占位引用**：对象确实不存在且属于下游任务领域（地理/势力/人物/古籍/道义等）时，正文 @引用 一律写为 `@类型.[TODO-序号]`（如 `@地名.[TODO-001]`、`@势力.[TODO-003]`）。类型必须与引用语法表一致（区域/地名/势力/人物/古籍/道义/资源/主角/伏笔/道义）。
> 2. **清单登记格式**：文件末尾「待创建条目」区块以表格或列表登记，每行字段：
>    `TODO-序号 | 类型 | 需求描述（不含专名，仅描述用途/约束/环境要求，如"丹药类物品卡常见产地，需灵气山脉环境"） | 候选名称建议（可选，提供符合题材风格的参考名称） | 预计引入卷（任务 01~04 可留空） | 提及位置（文件名+字段名）`
>    TODO-序号在当前文件内从 001 起连续递增。
> 3. **禁止自创专名**：需求描述与占位引用中均不得出现任何具体名称（山名、城名、势力名、人名、丹药名等）；如云端输出含自创专名视为格式违规，需重出。
> 4. **全局注册登记**：输出完成后，必须将「待创建条目」中的所有条目同步登记到 `02_数据库/00_TODO全局注册表.md`，确保全局唯一 ID 引用。
> 5. **下游回补机制**：对应下游任务（如任务02地理区域、任务03势力组织、任务05主角与核心配角）产出实名定稿后，由本地 Agent 执行占位符回补——将上游文件中的 `@类型.[TODO-序号]` 替换为实名，并勾选对应待创建条目；回补完成后引用闭合。

### 后期阶段规范（任务 05~11 及正文阶段）

任务 05~11（主角与核心配角、道义体系、文风节奏与爽感、书籍库、全书卷大纲、单卷大纲、单章细纲）及正文写作阶段，数据库已基本建立，**默认当场创建实体**；**仅**对下述两类前向/承重对象登记 TODO 占位符：

> **后期阶段实时创建规范**
>
> 1. **当场创建实体（默认）**：当引用的实体在现有数据库中不存在、且落在当前规划单元的职责与近场视界内（与本部/本卷同期登场，或纯本地一次性配角），必须直接为其赋予符合题材风格的正式名称（如 `@势力.[示例势力名]`、`@人物.[示例人物名]`、`@资源.[示例资源名]`）。
> 2. **随文新设实体卡片**：在输出末尾追加【随文新设实体卡片】区块，按对应卡片模板提供简要档案：
>    - 势力类：按 `03_势力组织模板` 提供三要素（核心诉求、行为模式、与主角关系）
>    - 人物类：按 `04_人物模板` 提供基础信息（姓名、身份、与主角关系）
>    - 资源类：按 `04_资源模板` 提供物品卡基础信息（名称、品级、用途）
>    - 地名类：按 `02_地理区域模板` 提供地名卡基础信息（名称、位置、特征）
>    - 其他类型：按对应模板提供必要字段
> 3. **自动落位规则**：本地 Agent 执行回填分割时，自动将【随文新设实体卡片】中的卡片提取出来，写入对应的数据库目录（如 `02_数据库/07_人物/` 或 `03_势力组织/`），并自动在对应数据库的总索引中追加该新实体行。
> 4. **名称一致性**：后续正文中引用该实体时，必须使用相同的名称，不得重复创建。
> 5. **前向引用 TODO（例外）**：以下两类对象**不**当场命名，改按早期阶段占位符格式登记「待创建条目」，且「预计引入卷」字段**必填**——
>    - ① **跨弧前向对象**：首次实质登场（行动/对话/被使用）在比当前规划单元更晚的部/卷；仅在当前产出中被提及、铺垫或列入远期蓝图。
>    - ② **承重对象**：最终反派、剧情关键法宝/功法、后期揭示的隐藏势力等，宜由其专属任务或引入所在卷的规划任务郑重设计，不在卷/章大纲里随手起名。
>    这类 TODO 同样登记进 `02_数据库/00_TODO全局注册表.md`；回补时机为其专属任务、或其「预计引入卷」所在部/卷规划任务运行时，不必等到正文阶段。
> 6. **正文阶段例外**：正文写作阶段若名称已在正文中出现，仍用实名登记；尚未登场的远期对象沿用上游前向引用 TODO。

## 与正文阶段任务的关系

本生成器负责**规划阶段**（设定、框架、大纲、细纲）的云端提示词拼装。**正文写作阶段**（写单章、战斗、突破、配角、抉择、版权自检、压抑检查）的指令骨架在 `00_通用模板/01_写作规则/01_系统指令.md`。两者共用同一套 @引用/ID 规范、六段固定骨架、以及本文件「输出文件与预建」「示例去污染规则」「规则引用纪律」。

拼装正文阶段云端提示词时：

1. **六段骨架照用**：【你的角色】（墨笔·写正文）→【必读规则】（`01_系统指令` 通用+任务指令 + `00_通用写作规则` + 本书文风模板 + 本书 `00_文风` 差异 + `07_单章细纲模板`/事件模板字段说明，全文内联，以文件名为区块标题）→【已有数据】（本章 `00_开篇状态.md` + 单章细纲全文 + 主角档案当前阶段 + 出场配角卡 + 场景地理卡 + WR 硬规则清单 + 本章道义/伏笔）→【任务】（`01_系统指令` 对应任务的执行要求，按本章细纲逐场景硬约束化）→【输出格式】（正文分场景 + 附录【待登记清单】：新角色 / 新伏笔 / 资源变更 / **本章状态变化点——散文列举「谁的什么，从什么变成什么」，不要求 7 列表格**；`01_状态履历.md` 由本地 Agent 按 `03_字段词表.md` 规范化）→【自检】（`00_通用写作规则` 第八章全清单 + 所选文风模板自检补充项 + 开篇三章契约 §六（仅章0001~0003）+ 世界规则层）。
2. **模板数量上限豁免**：正文阶段的「常驻」规则件（系统指令 / 通用写作规则 / 文风模板×2 / 单章细纲模板 / 履历模板）不计入「模板 ≤4」上限；事件模板（战斗/突破/事件感悟）按本章节拍「必用模板」列追加。
3. **文件与预建**（同「输出文件与预建」）：提示词存档 `05_工作区/《部》/《卷》/《章》/00_提示词/01_正文生成.md`；**预建**回填空文件 `05_工作区/《部》/《卷》/《章》/01_模型输出/01_正文生成.md`；**预建**正文目标文件 `10_正文/《部编号》_《部名》/《卷编号》_《卷名》/章XXXX.md`。战斗/突破/事件卡另拼时，存档/回填名 `02_<事件>卡.md`（同一章级 `00_提示词/`、`01_模型输出/`），目标 `03_规划/《部》/《卷》/01_事件/`。
4. **回填后本地流程**（写进提示词 `> 执行方式` 头）：Agent 落位正文到 `10_正文/…/章XXXX.md` → 把【待登记清单】的「本章状态变化点」按 `03_字段词表.md` + 各卡「动态字段清单」规范化成 7 列写入 `05_工作区/《部》/《卷》/《章》/02_状态/01_状态履历.md` → 跑 `merge_chapter_state.py --chapter-dir <本章目录>`（会自动刷新 `00_开篇状态.md` 与 `01_最新状态/`）→ 跑 `audit_consistency.py` 复查。**描述类字段变更需 LLM**（`llm.config.toml` + key）；未配置时本章履历只写运算类变更，描述类以 `>` 注记暂存、待配置后重折。
5. `01_系统指令` 中出现的模板文件名指代，拼装时一律指向提示词内对应的**内联区块标题**，不得保留为外部文件路径。
6. **禁脑补硬约束**（【必读规则】段加，正文任务必写）：
   > 细纲未列出的道具、机制、因果链、场景，一律不得自行添加。细纲留白处宁可不写，不得脑补。
   > 新增任何名词性设定须在同章产生叙事效果且可登记（新角色/新伏笔/资源变更）。
   【自检】段追加一条：「逐句检查——本段是否引入了细纲没有的东西？若有，删除或退回细纲层。」
   （拦截 ch1 #3 鞋底藏针、#5 消失的口粮 这类「细纲外脑补且不自洽」——多模型冷读循环见
   `03_任务技能/02_小说级/04_单章质量验收.md`。）
7. **回填后接冷读循环**（写进提示词 `> 执行方式` 头）：正文落位为**草稿**后，Agent 跑
   `review_manuscript.py --chapter-dir <本章目录>`（多模型冷读，见技能 04）→ 分诊分级 → 出修改
   提示词 → 用户贴回云端同对话改 → 重跑，≤3 轮收敛或用户 waive，方可标「待校验」。
