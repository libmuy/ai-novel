# 云端提示词生成器

> 多小说共用，只读。根据当前最新定稿数据生成自包含云端提示词，存入对应小说 `04_提示词/` 作为执行缓存；数据或前置状态变化后必须重拼装。
>
> 与 `00_通用模板/00_使用说明.md` 的关系：任务路由见本文件「规划任务路由表」；写单章等正文阶段的任务拼装，遵循 `00_通用模板/01_写作规则/01_系统指令.md` 的任务专用指令。

---

## 职责

根据小说名和任务编号，拼装一份自包含提示词。云端不会访问仓库，因此模板、定稿数据和任务要求必须内联；本地 Agent 只拼装，不生成设定。

## 固定骨架（六段，不改结构）

每个云端提示词固定为以下六段结构，拼装时逐段填充：

```
【你的角色】规划师/设定师，严格按给定模板与数据行事，禁止凭空编造；任务开始先以多轮问答引导用户补齐必要信息，信息齐备后再生成产出，禁止在信息缺失时凭空编造
【必读模板】……（本任务相关卡片模板/写作规则全文，以模板文件名为区块标题内联）
【已有数据】……（本小说已定稿数据，保证一致性）
【任务目标】生成 XX → 对应 01_设定/、02_数据库/ 或 正文卷N/00_规划/（若为任务00，先多轮引导采集概念信息，未齐备不生成）
【输出格式】严格按上文【必读模板】段内联模板的字段 + @引用/ID 规范；冲突以【已有数据】段为准
【验收自检】字段齐全 / @引用可解析 / 版权道义红线 / 数值符合资源体系
```

## 生成流程

1. 查任务路由，读取 `00_进度.md`；前置数据非「定稿」则只输出阻断报告。
2. 完整内联必读模板和定稿数据；模板最多 4 个，查表数据按需读取。
3. 写入任务参数、硬性格式、输出路径和“执行前需重拼装”提示；任务 00 保留多轮采集规则。
4. 按路由表存档提示词（合并任务 01+04、02+03 各一个存档，命名见「合并任务与产出簇模式」）；目标空文件和任务 01~04（含合并任务两簇）的回填空文件只创建、不覆盖。
5. 按「验收自检」检查。

## 增量追加规则（父文档索引同步）

> 默认全量生成；用户明确新增/追加子条目且已有索引和子文件为定稿时，切换为增量追加。

增量任务必须：
1. 在【任务目标】注明“增量追加，非全量重建”及对象名。
2. 在【输出格式】写明：
   - **父索引追加**：在对应总索引（或上一级文件）索引表中**追加**新条目行（名称｜一句话概况｜文件链接），与既有行合并，不得覆盖或重排既有内容；
   - **逐级补链**：多级结构（地理区域「世界→区域→地名」）新增中间/底层条目时，须自顶向下逐级补齐父文件索引（世界索引/地名索引），各级索引与子文件一一对应；
   - **子文件落位**：新增子文件按各模板「文件命名规则」命名；既有子文件仅追加本条目内容，不整体重写；
   - **引用闭合**：新增条目的 `@引用` 同步登记；引用对象未成卡时在文件末尾「待创建条目」登记。
3. 在【验收自检】增加“父索引已追加、逐级补链、既有内容未覆盖”。

生成步骤第 7 步预建空文件同样适用于增量追加：仅当目标文件不存在时预建，既有文件一律跳过（不覆盖）。

## 合并单文件输出模式（任务 01~04、08 及合并任务各簇可选）

> 用途：当用户要求"云端输出合并为一个文件 / 单文件下载"时启用，适用于任务 01~04、08（多文件拆分类：修炼体系、地理区域、势力组织、资源体系、书籍库）及「合并任务与产出簇模式」的各产出簇（每簇一份合并文件）。单文件任务（00、05~07、09~11）产出本为一个文件，不启用本模式。**粒度：每个任务一次合并**——一次云端执行的全部产出（总索引 + 全部子文件）写入**同一个 Markdown 文件**整体输出；用户把该文件保存到 `01_小说数据/<NN>_<小说名>/05_云端回填/<NN>_<任务名>_云端输出.md`，由本地 Agent 按 `00_通用模板/01_写作规则/07_云端回填分割规则.md` 分割回填到路由表「输出路径」对应数据文件。

拼装要求：
1. 【输出格式】在任务既有硬性要求外追加以下规则（内联模板字段本身不改动）：
   - 全部产出写入**单个 Markdown 文档**，整体输出、禁止拆成多个代码块；区块外只允许一个文件头说明段（文件名、任务名），不写汇总/目录；
   - 每个目标文件一个区块：区块开头独占一行 `<!-- FILE: <相对小说数据目录的输出路径> -->`，区块内容即该目标文件的**完整内容**（含文件内标题与区块标题），区块结束独占一行 `<!-- /FILE -->`；
   - 区块顺序与路由表「输出路径」列一致、按拆分粒度自顶向下组织：总索引区块在前，子文件区块依次在后（如任务02地理区域：总索引 → 各世界 → 各区域 → 各地名逐级）；
   - 内联模板中「产出合计 >1KB 时拆分为多文件」的规则在合并模式下不再要求云端物理拆分：区块粒度即拆分粒度，云端仅按层级组织区块，落位由本地 Agent 完成。
2. 【验收自检】在任务既有检查项外追加：
   - 每个 `<!-- FILE: -->` 路径与任务输出路径清单**精确一致**：无遗漏、无多余、无拼写偏差；
   - 区块闭合完整（`<!-- /FILE -->` 数量 = `<!-- FILE: -->` 数量，且顺序配对）；
   - 区块内字段齐全/@引用可解析/父索引同步等检查项与全量模式相同。
3. 存档文件名、预建空文件、路由表「输出路径」均**保持不变**；生成步骤第 6 步"一任务一文件"指提示词存档文件，与云端产出合并为单文件不冲突。预建空文件范围含 `05_云端回填/<NN>_<任务名>_云端输出.md`（生成步骤第 7 步）。
4. 存档文件头（`> 执行方式` 处）注明："本提示词为**合并单文件输出模式**：云端整体输出一个 Markdown 文件；保存到 `05_云端回填/<NN>_<任务名>_云端输出.md` 后由本地 Agent 分割回填。"

## 合并任务与产出簇模式（01+04、02+03 默认启用）

> 用途：规划阶段任务 01（修炼体系）与 04（资源体系）、02（地理区域）与 03（势力组织）存在强耦合，合并为两个合并任务。每个合并任务 = **一个云端提示词存档 + 一次会话执行**，会话内分两段产出簇，簇间不内联、直接引用会话内前簇产出。
>
> 与「合并单文件输出模式」的关系：各簇仍按该模式输出（`<!-- FILE: -->` 区块组织）；**产出文件仍按原任务名、每个簇一份**——簇1 产出保存到 `<NN>_<原任务1>_云端输出.md`，簇2 产出保存到 `<NN>_<原任务2>_云端输出.md`，由本地 Agent 按 `00_通用模板/01_写作规则/07_云端回填分割规则.md` 各自独立分割回填。预建空文件、产出文件命名、数据文件编号均与未合并时原样不变。

簇间流程（写入提示词【任务目标】/【输出格式】）：
1. **簇1** = 原任务1 全部 `<!-- FILE: -->` 区块（区块规范见「合并单文件输出模式」），区块顺序按路由表「输出路径」自顶向下；簇1 输出结束独占一行 `<!-- CLUSTER1 END -->`，随后停止，等待用户保存后再输入「继续」。
2. **簇2** = 原任务2 全部区块，直接引用簇1 会话产出，**不得重复输出或改写簇1 任何区块内容**。
3. **跨簇约束**：
   - 簇1 登记为「待创建条目」的 `@资源`/`@法宝`/`@势力` 等对象，若在簇2 成卡，须以簇1 引用中的精确名建卡，不得改名；
   - 地理区域卡「势力列表」直接写最终势力名，簇2 势力卡必须以该名单逐一成卡、名称精确一致；
   - 簇1 产出不完整（缺文件、缺字段、引用未登记）时，簇2 禁止开始，先补全簇1。
4. **兜底降级**：簇2 产出质量不足时，允许单独重跑簇2（此时簇1 已定稿数据改为【已有数据】内联，不再依赖同会话）。

拼装要求：
1. 存档文件名按合并命名 `NN+NN_<任务名>+<任务名>提示.md`（如 `01+04_修炼体系+资源体系提示.md`、`02+03_地理区域+势力组织提示.md`）；存档文件头（`> 执行方式` 处）注明合并模式与两簇产出文件名。
2. 【必读模板】仍只内联合并任务的两个原任务模板（各 2 个，≤4 上限）；【必读数据】为会话内簇间依赖，无需内联簇1 产出。
3. 【验收自检】在「合并单文件输出模式」检查项外追加：
   - 簇1/簇2 各自 `<!-- FILE: -->` 路径与对应原任务输出路径清单精确一致；
   - 簇2 未重复输出簇1 区块；簇1「待创建条目」对象名与簇2 成卡名精确一致；
   - 地理「势力列表」名 ↔ 簇2 势力卡标题逐一匹配，无拼写偏差。

## 占位符规范

拼装统一使用以下占位符标记待填/待确认项，**存档前必须全部替换为实际内容**：

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{{小说名}}` | 小说名称 | `我的小说` |
| `{{已有数据}}` | 内联的已定稿数据全文 | `01_设定/00_主角档案.md` 全文 |
| `{{任务参数}}` | 任务涉及的对象名/卷号/章节号 | `正文卷1`、`第一章` |
| `{{输出路径}}` | 产出文件的仓库路径 | `01_设定/00_小说概念.md` |

存档文件中不得残留任何 `{{占位符}}`。

## 验收自检

产出存档文件后逐项检查：
- [ ] 六段骨架齐全，文字与固定骨架一致（含多轮引导指令）
- [ ] 无残留 `{{占位符}}`
- [ ] 模板全文完整内联，以模板文件名为区块标题（≤4 个；超出已拆子任务）
- [ ] 提示词自包含：除提示词文件外无外部模板/数据文件路径引用
- [ ] 数据段只内联已定稿内容；缺失或未定稿时已输出阻断报告，未生成提示词
- [ ] 【任务目标】中任务编号、输出路径与路由表一致；任务00含"未齐备不生成"约束
- [ ] 存档文件名符合 `NN_<任务名>提示.md`（合并任务按 `NN+NN_<任务名>+<任务名>提示.md`），每任务一个文件
- [ ] 合并任务存档已在文件头注明合并模式与两簇产出文件名，内含簇间流程与跨簇验收自检
- [ ] 存档提示词【验收自检】含任务特定硬性检查（标题/格式/字数），非仅模板字段齐全
- [ ] 增量追加任务已在【输出格式】内联父文档索引同步规则、在【验收自检】含对应检查项
- [ ] 输出空文件已按路由表「输出路径」创建（已存在则跳过，未覆盖）；任务 01~04（含合并任务两簇，各按原任务名一份）已按第 7 步在 `05_云端回填/` 预建对应云端输出空文件（已存在则跳过）

## 与正文阶段任务的关系

本生成器负责**规划阶段**（设定、框架、大纲、细纲）的云端提示词拼装。**正文写作阶段**（写单章、战斗、突破、配角、抉择、版权自检、压抑检查）的指令骨架在 `00_通用模板/01_写作规则/01_系统指令.md`，两者共用同一套 @引用/ID 规范与固定骨架；需要拼装正文阶段的云端提示词时，同样把 `01_系统指令` 对应任务指令 + 模板全文 + 已定稿数据内联，存档到 `01_小说数据/<NN>_<小说名>/04_提示词/`。`01_系统指令` 中出现的模板文件名指代，拼装时一律指向提示词内对应的**内联区块标题**，不得保留为外部文件路径。
