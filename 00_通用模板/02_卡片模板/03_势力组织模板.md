# 势力组织模板

> 类型：卡片模板 · 定义字段与填写示例，用于生成/维护 `02_数据库/03_势力组织/` 文件夹及下属层级文件。

## 层级结构与文件拆分

本分类为多实体查表型数据，采用「总索引 + 子文件」多文件结构，**产出合计 >1KB 时按每势力一文件拆分**（≤1KB 保持单文件、全部写入总索引）。全部文件置于分类文件夹 `02_数据库/03_势力组织/` 内。

| 文件 | 内容 |
|------|------|
| `02_数据库/03_势力组织/03_势力组织.md` | 总索引：【势力索引】表格（势力名｜一句话概况｜势力文件链接）；≤1KB 时承载全部势力卡 |
| `02_数据库/03_势力组织/03_势力组织_<势力名>.md` | 势力文件：单个势力卡全文（三要素完整） |

**文件命名规则**：文件名 = 前缀 `03_势力组织` + `_<势力名>`，名称与势力卡名称、`@引用` 标识完全一致。

**父子关系规则**：总索引放「势力索引 + 文件链接」，子文件放「势力卡全文」；敌对/盟友/主角关系跨文件用 `@势力.[名称]` 引用，引用对象未成卡时登记「待创建条目」。增量追加新势力时，须同步在总索引【势力索引】表追加该势力行（势力名｜一句话概况｜势力文件链接），不得只新增势力文件而遗漏父索引更新。

**按需取分支示例**：某章涉及某势力，只加载 `02_数据库/03_势力组织/03_势力组织.md`（总索引）+ `02_数据库/03_势力组织/03_势力组织_<势力名>.md`；涉及敌对/盟友势力时再追加对应势力文件，禁止整目录全量灌入。

## 字段与示例

`(必)`=必填、`(条)`=条件必填，其余选填；示例值为格式参考，勿照抄。

### 势力卡 · [势力名称]

【基础档案】
| 字段 | 必填 | 说明与示例 |
|------|------|-----------|
| 势力名称 | (必) | 唯一标识名 |
| 体系/境界上限 | (必) | 主流修行体系与最高战力境界 |
| 地理位置 | (必) | 总部或主要活动区域，关联地理区域/地名（`@区域.名称` / `@地名.名称`） |
| 核心思想 | (必) | 一句话概括行事逻辑 |

【三要素】（缺一不可）
| 立场 | (必) | 站在哪一边，**必须具体到利益集团**，忌模糊"中立"（如："中立是为了维持交易抽成，依附于[某势力]庇护"） |
| 欲望 | (必) | 最想要什么，越具体越好，忌"变强""扩张" |
| 底线 | (必) | 何时掀桌子、翻脸或不惜一战 |

【生存逻辑】
| 经济来源 | (必) | 钱/资源从哪来？决定行为动机 |
| 武力构成 | (必) | 靠高手坐镇/靠人数/靠阵法/靠互克关系？ |
| 信息渠道 | | 怎么知道外界消息？决定反应速度 |

【关系网络】
| 敌对势力 | | 与谁有不可调和矛盾？根源是什么？ |
| 潜在盟友 | | 可与谁暂时合作？利益交汇点在哪？ |
| 内部裂缝 | | 内部派系斗争或历史遗留问题，主角可利用的切入点 |

【与主角关系】
| 当前状态 | | 友好/中立/敌对/利用/未知 |
| 关系演变轨迹 | | 预计如何变化？ |
| 主角价值 | | 该势力看中或忌惮主角什么？ |

【叙事功能】
| 故事作用 | | 提供资源/制造阻碍/映照主角/埋设伏笔/展示世界观 |
| 高光/崩塌事件 | | 势力在什么事件中达到影响力顶点或灭亡？关联具体事件时使用 EV-XXX 引用，禁止绑定具体卷号/章节号。 |

## 立场字段填写规范

- **错误**："中立""不偏袒任何一方""维持平衡"
- **正确**："表面上中立，实为某商会的外围眼线，靠商会庇护维持交易抽成"
- 立场必须回答：① 它依附于谁？② 从谁那获得生存资源？③ 若必须选边，选谁？为什么？

## 动态字段清单

> 声明本势力的哪些属性随剧情变化、需要进入状态追踪。字段名与类型以 `00_通用模板/03_字段词表.md`【势力类对象】为准。
> **关系类不在此声明**：势力间的敌对/结盟/隶属走 `06_关系` 一等对象或从属方单指针字段（隶属），见字段词表【关系类对象】。
