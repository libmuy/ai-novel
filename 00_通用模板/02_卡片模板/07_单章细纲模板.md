# 单章细纲模板

> 类型：卡片模板 · 定义字段与填写示例，用于生成/维护 `03_规划/《部编号》_《部名》/《卷编号》_《卷名》/规划_卷XX_章0001.md`。
>
> 写单章正文前的必读模板（见 `00_使用说明` 任务路由表）。没有细纲，禁止直接生成正文。本模板将一章拆为 2-5 个**场景**，各定义字数、功能、内容要点与钩子，保证节奏可控、不跑偏。

> **细纲是场景骨架，不是迷你提示词**（瘦身闸）：
> - 细纲只承载**本章特有**的东西——本章的场景切分、功能、钩子、本章的对象/数值/因果变化、本章的留白点。
> - **全书恒定的基准写指针、不重抄正文**：经济换算与计量口径、主角人设红线、金手指（异宝）在本卷的能力档位、禁用词、结构与节奏通则——这些逐章不变，正文提示词会另行内联本书 `01_设定/00_红线包.md`；细纲里只写「本章相关部分见红线包 §X」，抄一遍既涨 token 又制造两份口径。
> - 每个场景的「内容简述」**≤120 字**；场景下的红线提醒用一句指针（「本章古玉档位＝静默，见红线包 §二」），不逐条复述规则原文。
> - 例外——**本章特有的量必须在细纲内算清**：本章涉及的钱/时间/数量/克扣，写清单位、折算率、基数、结果（如「场景2 当日六枚三两→本应折一枚→判充公实付 0」），不留给正文临场编；但「三两废灵石折一枚」这类全书基准仍写指针。

## 出场对象

> 本章正文将出现（登场 / 被提及并影响本章 / 状态被改动）的全部对象 ID，逐个列出。
> **本表是本章出场对象的权威**，允许多于卷大纲节拍表——卷纲摘要只点主干对象（主角/主要配角/埋收 FH/核心法宝功法/关系变化双方），本章真正在场的次要配角、背景势力、场景地名在这一层按需补齐（配角优先复用 `02_数据库/07_人物/07_人物.md` 索引，无同职能既有卡再新建）。
> 供 `build_state_snapshot.py --write-chapter-openers` 按此清单拉取本章开篇状态；正文若引入未在此声明的对象，章后对账（`chapter_opener_drift` / `state_object_unregistered`）会报警——这同时是一道防「名字写错分裂出影子对象」的闸。
> 群像 / 一次性背景对象若确需进状态且不建卡，先登记 `05_工作区/02_状态/03_状态对象白名单.md`。
>
> **只放已建卡的对象或已登记白名单的群像**：`@人物.[]`/`@势力.[]`/`@物品.[]`/`@资源.[]`/`@地名.[]`/`@区域.[]` 名称类引用**方括号强制**（`audit` 的 `REF003` 会 error），且必须能在 `02_数据库/` 找到同名卡（否则 `PLAN002` error）。
> 配角一律 `@人物.[姓名]`（`@角色.X` 是 持有者/师承 字段的枚举值写法，别用在本表——漏方括号照样 `REF003` error）；主角只写 `@主角`。
> **无卡的一次性道具 / 消耗品**（矿镐、硬饼、粗布、干粮……）**不入本表**——写进场景「涉及资源」纯文本即可。
> **别把"容器"和它装的"消耗品"混为一谈**：判断某件随身物是否该入本表（或至少登记 `03_状态对象白名单.md`），看的是**容器本身**，不是它这次装了什么——药酒喝完了、旱烟抽完了确实一次性，但盛它们的那个葫芦、那杆烟锅子若会在角色间反复易手、且带着可辨认的具体特征（缺口、补痕、刻字……），它的持有者就是一条跨章事实，正文角色如果记错了在谁手上就是穿帮。这类"耐用容器/随身老物件"哪怕不值钱、算不上法宝，也该建状态对象（多数情况用白名单登记，不必强凑 `04_资源` 的九个标准类别）；纯装饰、从不换人换地方的标志性细节（如"手腕缠着母亲编的旧绳"）不受此限，可以继续留在正文自洽（ch0005 教训：周莽的缺嘴酒葫芦在 ch0004 交到主角手上后一直没建状态对象，ch0005 正文写成周莽又从自己腰间摸出同一只葫芦，作者通读才发现）。

【场景列表】（核心，每章 2-5 个场景）
| 场景序号 | (必) | 第1场景、第2场景…… |
| 场景地点 | (必) | 具体地点，关联地理区域/地名（`@区域.[名称]` / `@地名.[名称]`） |
| 场景字数 | (必) | 该场景预计字数，所有场景之和=本章总字数 |
| 场景功能 | (必) | 推进/揭示/转折/情感/铺垫（定义与占比见下） |
| 场景内容简述 | (必) | **≤120 字**，谁做了什么、结果是什么。只写本场事件，不复述通用规则/全书口径（那些写指针，见上「瘦身闸」）。**用故事内说法，禁「上一章 / 第N章 / 场景N / 章NNNN」这类结构指代**（会被云端照抄进正文；`audit` 的 `outline_leak` 会报）——写「昨夜那几株」不写「上一章的灵心草」 |
| 出场角色 | (必) | 使用 `@人物.[姓名]` 或 `@主角` 格式 |
| 涉及资源 | | 已在 `02_数据库/04_资源/` 建卡的资源用 `@资源.[名称]`；未建卡的通用名词（矿渣、草药、粗布等一次性道具）写纯文本，**不套 `@资源.[]` 方括号**——否则 `audit_consistency.py` 会按「引用了不存在的资源卡」报 error |
| 涉及伏笔 | | 使用 `@伏笔.<ID>` 格式（如 `@伏笔.FH-067`，ID 不加方括号） |
| 场景钩子 | (必) | 场景结束时留下的悬念，驱动进入下一场景 |

**场景功能说明**：推进（主角向目标前进一步：获线索/到新地/完成交易，占比40-50%）、揭示（释放新信息：世界观/背景/势力关系，15-20%）、转折（局势突变：被发现/被背叛/意外收获，10-15%）、情感（塑造关系或内心变化，10-15%）、铺垫（埋伏笔或造悬念，5-10%）。规则：每章至少 1 个推进 + 1 个情感或转折；连续两场景不得同为"推进"；"揭示"后必须紧跟"推进"或"转折"。

**场景间钩子设计**（禁止硬切）：
- 悬念钩子：A场景末留未解答问题，B场景回答或深化（"他打开盒子，里面不是丹药，而是一封信"）
- 动作钩子：A场景末主角做一个动作，B场景展示结果（"他拔出剑，向黑影刺去"）
- 情绪钩子：A场景末主角产生情绪，B场景展示其如何影响决策
- 信息钩子：A场景末释放一条信息，B场景展示谁对此做出反应

【章级钩子】
| 章末钩子类型 | (必) | 重钩（危机/变故/悬念激化）/ 轻钩（疑惑/反常/未说破） |
| 章末钩子内容 | (必) | 50字以内，具体写了什么让读者翻页？ |
| 与下章衔接点 | (必) | 下一章第一句必须承接什么？ |

【道义与感悟】
| 本章落地道义 | (必) | 对应 03_核心道义体系 中的哪条？（允许写"0.5条——仅埋设"） |
| 古籍引用 | | 若用古籍点题：写清**出处 + 短句**（供 Agent 内部参考）+ **正文用法**——挂哪本本书虚构书（`@书籍.[名]`），或按 `02_版权安全` §1.1 不具名化入（正文散文不出现现实书名/作者名） |
| 感悟触发场景 | | 在哪个场景中触发感悟？ |

【自检预检】
| 预估事件:感悟比例 | (必) | 如 "7.5:2.5"，必须在 7:3 ±15% 范围内 |
| 预估压抑/爽感 | (必) | 本章整体是压抑章还是爽感章？（连续压抑不得超过3章） |
| 新设定数量 | (必) | 本章计划引入的**新**设定数量（不得超过3个）。已有设定（写在设定层/主角档案里的能力、机制）的首次上场**不计入** |
| 轻埋伏笔不剧透 | (必) | 本章对某伏笔若是「埋设（轻埋/轻钩）」——细纲**不得写出该伏笔真相的具体因果 / 机制 / 关键人物**，只可写指向性线索（真相留给回收章）。写「本章无轻埋伏笔」或逐条确认 |
