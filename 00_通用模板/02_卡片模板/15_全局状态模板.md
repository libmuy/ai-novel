# 全局状态模板

> 对应数据：小说目录 `05_工作区/02_状态/01_最新状态/`（全书唯一权威对象状态存储）与冻结基线
> `05_工作区/02_状态/00_基线状态/`。
> **全部由 `02_工具/` 下的状态脚本覆盖写入，禁止手工编辑。** 本模板只描述格式，
> 供审计与人工阅读参照。字段名与类型的权威定义见 `00_通用模板/03_字段词表.md`。

## 目录结构

```
05_工作区/02_状态/01_最新状态/
├── 00_说明.md            手写
├── 00_同步状态.md         脚本写：manifest（折叠至章 / 时间 / 计数），非权威
├── 00_持有物品反查.md      脚本写：从 物品.* 的「持有者」反查的派生视图，非权威
├── 01_角色/  01_角色.md（索引）  01_角色_<名>.md ...
├── 02_物品/  ...
├── 03_势力/  ...
├── 04_财务/  ...
├── 05_世界/  ...
├── 06_关系/  06_关系.md（索引）  06_关系_<甲>&<乙>.md ...
└── 99_其他/  ...          对象ID前缀不属五大类的兜底
```

对象 ID 前缀 → 类目：`角色.→01_角色` `物品.→02_物品` `势力.→03_势力`
`财务.→04_财务` `世界.→05_世界` `关系.→06_关系`。对象名里 `/ \ : * ? " < > |` 及控制字符按
`%XX` 编码进文件名。**读取以文件内表格第 1 列「对象ID」为准，文件名只是派生物。**

**关系对象 ID** `关系.<甲>&<乙>`：分隔符必须是 ASCII `&`（恰一个），两端名字按 Unicode
码位排序后拼接——同一对关系物理上只有一个文件，双边不一致从结构上不可能。「甲」= 排序
在前者。对称关系（敌对/结盟/血亲/同门…）才建关系对象；非对称关系（持有→`物品.Y 的「持有者」`、
师承→`角色.X 的「师承」`、隶属→`势力.X 的「隶属」`）记在从属方字段上，反向由脚本派生。

`00_基线状态/` 布局与 `05_工作区/02_状态/01_最新状态/` 完全相同，但只读不可变、无 `00_同步状态.md`。

## 每对象文件格式（`NN_类目/NN_类目_<名>.md`）

```markdown
# 全局状态 · 角色.示例角色

> 由状态脚本自动写入，请勿手工编辑。
> 对象ID: 角色.示例角色

| 对象ID | 字段 | 类型 | 值 |
| --- | --- | --- | --- |
| 角色.示例角色 | 境界 | 运算-枚举 | 炼气一层 |
| 角色.示例角色 | 内力值 | 运算-数值 | 80 |
| 角色.示例角色 | 所在地 | 描述 | 灰壤凡域·墨骨巷 |
```

- 标准 4 列，无履历的元数据列。
- `> 对象ID:` 头行与每行第 1 列必须一致（审计项 `global_state_header_mismatch`）。
- 基线文件的头注为 `> 创世基线快照 · 只读不可变（写第 1 章前一次性生成）。`

## 持有物品反查 `00_持有物品反查.md`

脚本扫全部 `物品.X 的「持有者」` 字段，按持有者分组的只读派生视图——**非权威**。
权威数据永远是各 `物品.X` 对象文件的「持有者」字段。用于「某人身上有哪些物品」的查阅。

## 语义

`05_工作区/02_状态/01_最新状态/` == `00_基线状态/` ⊕（按章节路径顺序折叠全部 `01_状态履历.md`）。
一致性由 `audit_consistency.py` 的 `state_drift` 检查保证。关系 ID 规范由 `relation` 规则
（`RELATION001`）保证，关系悬挂由 `RELATION002` 提示。
