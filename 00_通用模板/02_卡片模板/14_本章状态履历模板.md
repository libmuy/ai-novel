# 本章状态履历模板

> 文件规范位置：`05_工作区/《部》/《卷》/《章》/04_本章状态履历.md`
> 维护规范：正文生成/定稿时同步产出，仅记录本章新产生的增量状态变化。
> 章末由 `python3 02_工具/merge_chapter_state.py --chapter-dir <本章>` 把本表折叠进
> 唯一权威状态存储 `05_工作区/00_全局/01_最新状态/`（每对象一文件）。**本章不再产出 `03_本章初始状态.md`。**
> 语法约束：
> - 运算-数值：使用 `+N` 或 `-N` (如 `-30`)
> - 运算-枚举：直接写目标枚举 (如 `炼气二层`)
> - 运算-列表：使用 `+X,-Y` 格式 (如 `+培元丹,-破草鞋`)
> - 描述：直接写 Markdown 自由文本描述
> - 终态标记：`活跃` / `死亡` / `退场` / `暂离`

## 表格列说明

本表共 7 列。前 4 列为**权威计算列**（参与 `merge_chapter_state.py` 合并）；
后 3 列为**元数据列**，仅供人工检索、审计与级联排查，**不参与任何类型合并计算**：

| 列 | 含义 | 取值 |
|---|---|---|
| 章节号 | 产生该变更的章节编号 | 如 `0001` |
| 变更时间 | 该变更被记录/定稿的时间 | 如 `2026-08-30`；未知可写 `-` |
| 变更类型 | 该对象-字段在本章的变更性质 | `新建` / `修改` / `移除` |

- `新建`：该对象-字段本章首次出现（描述类首次出现直接字面写入，无需 LLM）。
- `修改`：在已有值基础上做数值运算、枚举替换、列表增删或描述覆盖。
- `移除`：该对象-字段本章后不再追踪（仅标记，合并仍按「值」列语法处理）。

> 「描述」类字段有实质变更时，`merge_chapter_state.py` 会把本次全部待合并描述字段打包
> 成**一次** LLM 调用（旧文本 + 新文本合并不丢信息），合并结果写进独立的 append-only
> 缓存 `05_工作区/00_全局/00_描述合并缓存.jsonl`。**本表永不被脚本改写**，「值」列与
> 「变更类型」列始终是人工写入的原文，不会出现 `描述合并`。**LLM 不可用且本章确有待
> 合并描述变更 → 合并中止、退出码 2、不写任何文件**（纯运算章节无需 key）。
