# 修仙小说创作模板库 · 使用说明（v3.1）

> Agent 执行任务前必读。本文件唯一规定引用、ID、路由、状态和加载边界；目录说明见 `99_速查手册.md`，不作为任务路由依据。

## 技能层

技能分为三层，不依赖特定 Agent 宿主：

1. **系统级技能模板**：`00_通用模板/03_任务技能/01_系统级/index.md`，定义跨小说的审查和规则维护流程。
2. **共用小说级技能模板**：`00_通用模板/03_任务技能/02_小说级/index.md`，定义项目状态、回填、章节对账和验收流程。
3. **本书技能配置**：各小说 `05_任务/00_技能/index.md` 与 `本书技能配置.md`，只写本书差异。

技能负责“如何执行”；模板负责字段；写作规则负责约束；小说数据负责内容。技能索引和配置不是定稿数据，不参与正文设定引用。加载技能后仍必须遵守本文件的路由、引用、ID、状态和验收规则。

## 架构规范

三层职责划分（设定层/规划层/创作层）、表现范式定义、软约束原则与 ID 引用原则，详见 `00_系统架构规范.md`。本文件规定引用、ID、路由、状态和加载边界；架构规范规定职责边界与创作自由度。两者互补，不冲突。

## 引用语法

所有模板中的"关联"字段，统一使用以下语法：

| 引用类型 | 语法格式 | 示例 |
|---------|---------|------|
| 关联角色 | `@人物.[姓名]` | `@人物.[示例人物名]` |
| 关联主角 | `@主角` | `@主角`（固定写法，无需姓名） |
| 关联势力 | `@势力.[势力名称]` | `@势力.[示例势力名]` |
| 关联伏笔 | `@伏笔.[伏笔ID]` | `@伏笔.V1-C03-001` |
| 关联资源 | `@资源.[资源名称]` | `@资源.[示例资源名]` |
| 关联区域 | `@区域.[区域名称]` | `@区域.[示例区域名]` |
| 关联地名 | `@地名.[地名]` | `@地名.[示例地名]` |
| 关联道义 | `@道义.[道义ID]` | `@道义.DY-001` |
| 关联古籍 | `@古籍.[书名]` | `@古籍.[示例书名]` |

**规则**：必须使用上述格式，名称大小写完全一致；上表示例仅为语法格式示范、非本小说预设对象，实际引用名称须与已定稿数据一致。

**方括号是强制的**：`@人物`/`@势力`/`@区域`/`@地名`/`@资源`/`@古籍` 的名称**必须**用方括号包起来（`@势力.[黑石会]`，不是 `@势力.黑石会`）。名称是任意中文、没有分隔符，不加方括号时解析器无法确定名称在哪里结束，会把后续正文一起吞进对象名，导致引用校验大面积误报。`@主角` 是固定写法、无名称，不加方括号；`@道义.DY-001`、`@伏笔.<ID>` 用 ID、可不加方括号（但加了也不错）。`audit_consistency.py` 的 `REF001` 会拦无方括号的名称引用。

对象确实不存在时，在文件末尾登记「待创建条目」：
   ```markdown
   ## 待创建条目
   - [ ] @地名.[TODO-001]（类型：地名；需求：丹药类物品卡常见产地，需灵气山脉环境；提及位置：04_资源_材料.md）
   - [ ] @势力.[TODO-002]（类型：势力；需求：垄断特定材料收购的商会性质势力；提及位置：04_资源_材料.md）
   ```

**规划阶段占位符规则**：云端规划任务（任务 00~11）产出中，凡登记「待创建条目」一律**禁止自创具体名称**；@引用 使用 `@类型.[TODO-序号]` 占位符（如 `@地名.[TODO-001]`），文件末尾「待创建条目」清单登记 `TODO-序号 ｜ 类型 ｜ 需求描述（不含专名，仅描述用途/约束/环境要求） ｜ 预计引入卷（部/卷编号；任务 05~11 的前向引用必填，任务 01~04 可留空） ｜ 提及位置`；TODO-序号在当前文件内连续递增。

**何时建 TODO、何时当场创建**（判据不是"第几号任务"，而是"引用对象是否在当前任务的设计职责与时间视界之内"；分阶段细则见 `04_提示词/00_云端提示词生成器.md`【实体创建规范（分阶段）】）：
- **任务 01~04**（修炼体系/资源/地理区域/势力组织）：数据库尚未建立，缺失的下游领域对象（地理/势力/人物/古籍/道义等）一律登记 TODO 占位符。
- **任务 05~11**（主角与核心配角、道义、文风、书籍库、卷/单卷/单章大纲）：默认**当场创建**落在当前设计职责与近场视界内的对象（与当前规划单元同部/同卷登场、或纯本地一次性配角），并在输出末尾附【随文新设实体卡片】；**仅两类可登记前向引用 TODO**——① 首次实质登场在比当前规划单元更晚的部/卷；② 承重对象（最终反派、剧情关键法宝、后期揭示的隐藏势力）宜由其专属任务郑重设计。前向引用 TODO 的「预计引入卷」字段必填。
- **正文阶段**（写单章/战斗/突破等）：名称已在正文中出现的用实名登记，不受占位符限制；尚未登场的远期对象沿用上游前向引用 TODO。

加载多个数据文件时检查引用；只在确认对象不存在时登记待创建，不得把未加载误判为缺失。

**引用解析状态**：
- **已加载且存在**：可直接引用。
- **已知存在但本次未加载**：保留原引用，不得登记为待创建条目；需要校验时再按需加载目标文件。
- **确实不存在**：在当前数据文件末尾登记「待创建条目」；规划阶段云端产出须按占位符规则登记；并将当前任务标记为「待校验」，不得宣称引用闭合。

**待创建条目回补**：TODO 在其归属专属任务（如地理区域/势力组织/人物）生成实名定稿后回补；前向引用 TODO 也可在其「预计引入卷」所在的部/卷规划任务运行时回补，**不必等到正文阶段**。回补由本地 Agent 将上游文件中的 `@类型.[TODO-序号]` 替换为实名，并勾选对应待创建条目；回补完成后引用闭合。只有确属章内局部、无归属专属任务的 TODO 才在对应正文章节写作时回补。

## ID 编号

ID 按卡片类型使用下表格式，不得自创变体：

| 卡片类型 | 格式 | 示例 | 说明 |
|---------|------|------|------|
| 伏笔登记 | `FH-序号` | `FH-001` | **全书唯一、全局分配、永不复用**。唯一权威登记表是 `03_规划/00_伏笔总纲.md`（FH 总账）：新伏笔号 = 总纲已用最大号 +1；设定/地理卡「相关事件/伏笔」字段、各卷伏笔册的 FH 含义均以总纲为准，冲突时改设定层/伏笔册、不改总纲。新增任何伏笔（含地理卡风味钩子）必须同步在总纲登记。埋设位置记在伏笔册「埋设位置」字段 |
| 主角突破 | `BP-卷号-序号` | `BP-V1-001` | 章节信息记在突破卡"突破章节"字段 |
| 战斗结算 | `BT-卷号-序号` | `BT-V1-003` | 章节信息记在战斗卡"发生章节"字段 |
| 资源道具 | `RES-类别-序号` | `RES-DAN-003` | 类别枚举：DAN丹药/FAB法宝/CLI材料/LS货币(灵石)/GF功法/FU符箓/LIN妖兽(灵兽)/OTHER（前缀 LS/LIN 为历史兼容写法，现指货币/妖兽大类） |
| 道义条目 | `DY-序号` | `DY-001` | 全书唯一 |
| 世界基本法则 | `WR-序号` | `WR-001` | 全书唯一；见 `01_设定/00_小说概念.md`【世界基本法则】区块 |
| 待创建条目 | `TODO-序号` | `TODO-001` | 用于数据文件"待创建条目"列表及正文中的占位引用（`@类型.[TODO-序号]`）；文件内连续递增 |

## 世界基本法则（世界观最底层约束）

> 存放位置：`01_设定/00_小说概念.md`【世界基本法则】区块（随任务00产出），是**世界观最底层约束**，不替代修炼体系与世界观详细设定。规则 ID 格式 `WR-序号`（见上表）。

**职责**：定义整个世界"什么可以发生、什么不能发生、什么通常成立、什么目前未知"。具体境界/功法/丹药/法宝/宗门/国家/城镇/山川/NPC/资源/地图/势力一律留给下游世界观模块，禁止提前塞入。

**状态三态**：
- **硬规则**：整个小说原则上绝不可违反。
- **软规则**：通常成立，允许极少数经过明确铺垫的例外。
- **未知规则**：作者故意不确定或后期揭示。**未知规则必须保持未知，禁止 AI 自行补全**，除非后续任务明确允许揭示；可作伏笔来源（类型=世界观揭秘）。

**规则优先级**：`世界硬规则 → 世界软规则 → 修炼体系规则 → 具体能力规则 → 剧情中的具体行为`。下层规则不得违反上层硬规则；下层设计与世界硬规则冲突时，**必须修改下层设计，而不是修改世界基本法则**。

**稳定性保护**：世界基本法则属高优先级定稿数据。原则「用户确认 → 世界基本法则定稿 → 下游只能引用 → 不得自行修改」。剧情出现疑似违反/揭示法则的异常现象时，登记到 `05_工作区/《部》/《卷》/《章》/04_本章状态履历.md`（世界对象状态），**不得修改世界基本法则**；未知规则揭示须走伏笔系统，经用户确认后方可更新概念卡规则状态。后续 AI 发现剧情与世界基本法则冲突时：报告冲突、指出具体冲突位置、给出修改剧情/下层设定的建议，**不得自动修改世界基本法则**。

## 规则冲突检查（复用既有校验机制）

> 世界规则 → 修炼体系 → 资源 → 人物能力 → 剧情事件 → 正文 逐层检查。冲突时统一处理：报告 + 指出冲突位置 + 修改下层设计；**禁止**为让剧情成立而自动修改世界硬规则。

| 检查层级 | 检查入口 |
|---------|---------|
| 世界规则 → 修炼体系/资源/地理/势力 | 对应任务云端提示词【执行要求】+ `07_云端回填分割规则` 校验「任务特定红线」 |
| 世界规则 → 人物能力 | 任务05 提示词约束 + 人物卡/主角档案校验 |
| 世界规则 → 剧情事件 | `00_通用写作规则` 第八章【世界规则层】自检 |
| 世界规则 → 正文 | 正文阶段提示词红线（`01_系统指令`）+ 第八章【世界规则层】 |
| 系统性审查 | `03_任务技能/01_系统级/01_系统规则审查.md`（世界规则一致性维度） |

任一前置（含概念卡【世界基本法则】）非「定稿」时，下游任务只输出阻断报告，不得继续生成。

> **Token 控制**：单次任务加载的模板文件不得超过 **4个**。只统计实际读取的卡片模板、写作规则和验收规则；系统指令不重复计数。超出则优先加载"必读"，将"可选"拆为子任务单独执行。数据文件按需读取，不以文件数量代替 Token 判断；阶段中间产物不得作为定稿数据。

> **前置阻断**：任务路由表中的必读数据必须全部为「定稿」。任一前置数据缺失、状态不是「定稿」或引用未闭合时，Agent 只能输出阻断报告（缺失项、当前状态、下一步任务），不得用假设、占位内容或旧提示词继续生成。

> **提示词时效**：`05_工作区/01_提示词/` 中的提示词是可重新生成的执行缓存，不是永久有效的数据副本。每次交付云端提示词前，必须依据当前 `00_进度.md` 和最新定稿数据重新拼装；已有提示词若内联数据或前置状态已变化，禁止直接执行。

> **按需追加**：单章细纲恒含 `07_单章细纲模板` + `00_通用写作规则`；章0001~0003 追加 `05_开篇三章设计指南`；按本章节拍「核心事件类型」追加 1 个事件模板（抉择/道义·感悟/闭环→`10_事件与感悟卡模板`，冲突/战斗→`08_战斗结算模板`，突破/晋升→`09_主角突破卡模板`）；含古籍追加版权规则，设计资源追加资源规则。合计 ≤4，超出拆子任务。

> **分类拆分规则**：多实体/查表型分类（修炼体系、地理区域、势力组织、资源、书籍库）数据产出**合计 >1KB 时**，按各模板「层级结构与文件拆分」定义的粒度拆分为「总索引 + 子文件」（≤1KB 保持单文件；地理区域按世界→区域→地名、书籍库按每书一文件恒拆分，不设 1KB 阈值）；加载时只读「总索引 + 涉及条目文件」，按需取分支，禁止整目录全量灌入。**规划层结构**：总索引存放在 `03_规划/规划.md`，各部规划存放在 `03_规划/《部编号》_《部名》/规划_《部名》.md`；单卷详细大纲由任务 10+（单卷大纲生成）产出，落位 `03_规划/《部编号》_《部名》/《卷编号》_《卷名》/规划_《卷名》.md`；单卷伏笔跟踪册落位 `03_规划/《部编号》_《部名》/《卷编号》_《卷名》/00_伏笔册_《卷名》.md`；单章细纲由任务 11 产出，落位 `03_规划/《部编号》_《部名》/《卷编号》_《卷名》/规划_卷XX_章XXXX.md`；事件卡落位 `03_规划/《部编号》_《部名》/《卷编号》_《卷名》/01_事件/`。**增量追加**子条目（新增体系/世界/区域/地名/势力/类别/物品卡/书籍/卷大纲）时，须同步在父文档（总索引或上一级文件）索引表追加对应行与文件链接，逐级补链，不得只新增子文件而遗漏父索引。

> **跨章滑动窗口衔接机制**：在每个单章细纲（`07_单章细纲模板`）头部，自动包含 `## 0. 上下文滑动窗口 (Sliding Window Context)` 区块（包含`上章末尾摘要 (300字)`与`上章结尾原文最后 500 字`）。当第 N 章正文生成结束定稿后，Agent 自动提取摘要与结尾原文写入第 N+1 章细纲文件的滑动窗口中；正文生成时紧密承接滑动窗口中的上章末尾场景与语气。

> **查表型数据**：`02_数据库/01_修炼体系/`（总索引+每体系一文件）、`02_数据库/04_资源/`（总索引+每类别一文件）为大型查表文件，除卷大纲/新体系设计等需全量对照的任务外，一律**按需取条**——只读本章/本事件涉及的体系、资源条目文件，禁止整文件加载进上下文。

> **单章基线**：常驻 `01_系统指令 + 00_通用写作规则_生成版 + 00_文风_XX（本书所选文风） + 00_主角档案_当前阶段`；不替代路由必读数据，其余按需加载。

> **注意**：`05_开篇三章设计指南` 仅在**第一卷**的卷大纲设计时作为附加模板加载，其他卷不使用。

> **配角复用优先**：任务 09/10/11 与"开篇三章设计"生成【新出场配角】【关系变化】等字段时，**必须先读 `02_数据库/07_人物/07_人物.md` 总索引**，落在当前卷核心地点、且既有卡已覆盖该职能（监工/管事/工友/老矿工/青梅竹马等）的角色**一律复用既有卡的姓名与设定**，禁止另造同职能新名。确需新配角时才当场建卡（`04_人物模板`）并附【随文新设实体卡片】。

> **伏笔册维护规则**：
> - **唯一权威**：`03_规划/00_伏笔总纲.md`（FH 总账）登记全书每个 FH-序号的名称与权威含义。卷级伏笔册（`00_伏笔册_《卷》.md`）与设定/地理卡只是它的下游——含义冲突时改下游、不改总纲。
> - ① 新埋伏笔的 `FH-序号` = **总纲已用最大号 +1**；新增后立即在总纲登记（地理卡新增的风味钩子同样要登记）。
> - ② 卷级伏笔册是**追加式**文件：**禁止重写、删除、改写他卷或上游已登记的伏笔条目**；只登记**本卷实际出现**的伏笔（新埋/推进/回收），未在本卷出现的历史伏笔不进入本册。
> - ③ 生成卷大纲/开篇三章前，必读数据须含 `03_规划/00_伏笔总纲.md` + 本卷伏笔册（若存在）。

> **必读数据覆盖检查**：新增或修改路由表任一任务行前，先展开该任务对应的全部「必读模板」，列出模板中所有会产生 `@引用` 的字段；「必读数据」列必须逐一覆盖这些引用可能指向的上游分类总索引，不得遗漏。引用同名不同颗粒度的文件时（如全书级"全书卷大纲"与分卷级"卷大纲"），必读数据列必须写完整相对路径，禁止用简称，避免被误认成同一文件。涉及【世界基本法则】（WR 规则）引用的任务，必读数据列须覆盖 `00_小说概念` 或其相关小节，保证 WR 规则可解析。

## 动态工作区规则

> `05_工作区/` 记录生产任务与每章状态履历，是生产现场与动态状态对账层。
> 状态的唯一权威存储是 `05_工作区/00_全局/01_最新状态/`（每对象一文件，脚本覆盖写入）；
> 冻结基线在 `05_工作区/00_全局/00_基线状态/`。

**章级别工作区结构**：

```
05_工作区/01_第01部/01_卷01/章0001/
├── 01_提示词.md            # 本章下发 Prompt 存档
├── 02_云端回填.md          # 云端大模型产出的原始 Output
├── 04_本章状态履历.md      # 本章状态变化 (结构化)；章末折叠进 05_工作区/00_全局/01_最新状态/
└── 05_校验结果.md          # 自动化脚本校验与修复日志
```

**章末**：`python3 02_工具/01_小说通用工具/merge_chapter_state.py --chapter-dir <本章>` 把履历折叠进
`05_工作区/00_全局/01_最新状态/`。描述类字段有实质变更时会调一次 LLM 智能合并（见 `03_字段词表.md`）。

**历史归档**：无法确定归属的旧云端输出统一归入 `05_工作区/00_历史回填/`。

**原则**：
- 动态工作区中的提示词与回填是生产过程数据，不是正式小说数据
- 正式数据只存在于 `01_设定/`、`02_数据库/`、`03_规划/`、`05_工作区/00_全局/01_最新状态/`、`05_工作区/`（章级履历）、`10_正文/`
- 工作区中的云端原始输出不得作为后续任务的权威输入
