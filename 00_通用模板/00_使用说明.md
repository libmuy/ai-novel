# 修仙小说创作模板库 · 使用说明（v3.0）

> 类型：入口索引 · Agent 执行任务前必读：引用语法、ID 编号规范、任务路由表。
>
> **索引类信息**（目录结构、三类文件区别、命名规范、使用原则、必填/选填说明、模板联动速查表）独立存放于 `99_速查手册.md`，人类查阅用，Agent 任务无需加载。任务加载关系一律以本文件「Agent 任务路由表」为准。

## 引用语法规范（跨模板关联基础设施）

所有模板中的"关联"字段，统一使用以下语法：

| 引用类型 | 语法格式 | 示例 |
|---------|---------|------|
| 关联角色 | `@配角.[姓名]` | `@配角.张三` |
| 关联主角 | `@主角` | `@主角`（固定写法，无需姓名） |
| 关联势力 | `@势力.[势力名称]` | `@势力.青云宗` |
| 关联伏笔 | `@伏笔.[伏笔ID]` | `@伏笔.V1-C03-001` |
| 关联资源 | `@资源.[资源名称]` | `@资源.聚气丹` |
| 关联区域 | `@区域.[区域名称]` | `@区域.青云山` |
| 关联地名 | `@地名.[地名]` | `@地名.青云坊` |
| 关联道义 | `@道义.[道义ID]` | `@道义.DY-001` |
| 关联古籍 | `@古籍.[书名]` | `@古籍.某某志` |

**规则**：
1. Agent 填写数据必须用此格式，不得用纯文本或模糊指代。
2. 引用的对象不存在时，在数据文件末尾"待创建条目"登记，格式：
   ```markdown
   ## 待创建条目
   - [ ] @配角.某某某（于第X章出场，需补充配角卡）
   - [ ] @资源.某某某（于第X章获取，需补充资源卡）
   ```
3. 每次加载多个数据文件时，自动检查所有引用能否在已加载文件中找到；找不到标记"待补全"。
4. 引用标识符**大小写敏感**，必须与目标条目实际名称完全一致。

## ID 编号规范（跨卡片唯一标识）

不同卡片 ID 前缀不同（用于区分类型），结构统一为"前缀-卷号[-章节]-序号"。**Agent 填写必须用下表格式，不得自创变体**：

| 卡片类型 | 格式 | 示例 | 说明 |
|---------|------|------|------|
| 伏笔登记 | `V卷号-C章节号-序号` | `V1-C03-001` | 章节必填，精确到埋设章 |
| 主角突破 | `BP-卷号-序号` | `BP-V1-001` | 章节信息记在突破卡"突破章节"字段 |
| 战斗结算 | `BT-卷号-序号` | `BT-V1-003` | 章节信息记在战斗卡"发生章节"字段 |
| 资源道具 | `RES-类别-序号` | `RES-DAN-003` | 类别枚举：DAN丹药/FAB法宝/CLI材料/LS灵石/GF功法/FU符箓/LIN灵兽/GJ古籍/OTHER |
| 道义条目 | `DY-序号` | `DY-001` | 全书唯一 |
| 待创建条目 | `TODO-序号` | `TODO-001` | 仅在数据文件"待创建条目"列表中使用 |

**规则**：
1. 序号在同类卡片内连续递增，禁止跳号或复用。
2. 同一章涉及多张同类型卡片时序号递增（如 `BT-V1-003`、`BT-V1-004`）。
3. 未定章节的事件卡（突破、战斗）允许暂缺章节信息，但回收/引用时必须补充。
4. 引用卡片一律用其 ID（如 `@伏笔.V1-C03-001`），禁止用文字描述替代。

## Agent 任务路由表（生成/续写前必读）

执行任一任务时，**只加载本表"必读"列中的文件**，不得加载全部。

> **模板 vs 数据**："必读模板" = `00_通用模板/` 下的**卡片模板**（定义字段，要填的表）与**写作规则**（行为约束，要守的规矩）；"必读数据" = `01_小说数据/<NN>_<小说名>/` 下已填写的定稿数据。模板决定"怎么写"，数据决定"写什么"。两类文件区别见 `99_速查手册`「三类文件的区别」。
>
> **数据位置**：设定卡在 `02_设定/`（每个分类一个 `NN_分类/` 文件夹，文件夹内放该分类数据文件）、全书级蓝图在 `01_规划/`、卷级规划与正文在 `正文卷N/`（卷大纲/单章细纲在 `正文卷N/00_规划/`）、动态状态台账在 `03_状态/`。完整目录结构见 `99_速查手册`。表中数据文件均省略目录前缀，加载时按此规则定位。

| 任务类型 | 必读模板 | 必读数据 |
|---------|---------|---------|
| 新建小说 | 06_新建小说清单, 00_小说级AGENTS模板 | 无（新书，无既有数据） |
| 生成卷大纲 | 02_地理区域模板, 03_势力组织模板, 03_核心道义体系, 06_卷大纲模板 | 01_修炼体系, 03_势力组织, 05_核心道义 |

| 设计战斗/冲突（含跨体系） | 08_战斗结算模板 | 07_配角卡（参战角色）, 03_势力组织 |

> **Token 控制**：单次任务加载的模板文件不得超过 **4个**。超出则优先加载"必读"，将"可选"拆为子任务单独执行。

> **事件卡触发（按需追加，用完即弃）**：写单章时，本章含两难抉择/感悟闭环 → 追加 `10_事件与感悟卡模板`；含战斗 → 追加 `08_战斗结算模板`；含突破 → 追加 `09_主角突破卡模板`；含跨体系战斗 → 追加 `08_战斗结算模板`「跨体系冲突」区块；古籍点题 → 追加 `06_版权安全`（古籍弹药库）。设计新资源 → 追加 `12_资源道具卡模板`。均需先填 `07_单章细纲模板`。

> **分类拆分规则**：多实体/查表型分类（修炼体系、地理区域、势力组织、资源分级）数据产出**合计 >1KB 时**，按各模板「层级结构与文件拆分」定义的粒度拆分为「总索引 + 子文件」（≤1KB 保持单文件）；加载时只读「总索引 + 涉及条目文件」，按需取分支，禁止整目录全量灌入。

> **查表型数据**：`02_设定/01_修炼体系/`（总索引+每体系一文件）、`02_设定/04_资源分级/`（总索引+每类别一文件）为大型查表文件，除卷大纲/新体系设计等需全量对照的任务外，一律**按需取条**——只读本章/本事件涉及的体系、资源条目文件，禁止整文件加载进上下文。

> **写单章最小上下文**：上下文常驻【01_系统指令 + 00_文风节奏 + 00_主角档案】，其余文件按需追加、用完即弃（详见 01_系统指令「最小上下文原则」）。

> **注意**：`05_开篇三章设计指南` 仅在**第一卷**的卷大纲设计时作为附加模板加载，其他卷不使用。

## 战斗标准流程

任何涉及主角的战斗（含跨体系）按 `08_战斗结算模板`「跨体系战斗标准流程」执行：**战前设计 → 正文生成 → 战后结算**三段。`08_战斗结算模板` = 战前设计 + 战后结算同卡：战前解决"为什么打""双方理念差异""体系互克如何体现"；战后解决"打完代价是什么""谁死了""消息怎么传"。

---

## 单章生成后一站式自检清单

> **唯一校验入口**：生成任意一章正文后，执行 `00_文风与节奏规范` **第八章「单章一站式自检清单」**，全部勾选通过方可存档。
>
> 各层级校验项（结构层/爽感与压抑层/数据层/版权层/主角人设层/资源与经济层/事件设计层）已全部收敛到 00_文风，本文件不再重复列出，避免规则多源、口径不一。
