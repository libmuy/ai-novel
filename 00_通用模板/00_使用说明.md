# 修仙小说创作模板库 · 使用说明（v3.1）

> Agent 执行任务前必读。本文件唯一规定引用、ID、路由、状态和加载边界；目录说明见 `99_速查手册.md`，不作为任务路由依据。

## 技能层

技能索引位于 `03_任务技能/`，分为系统级和小说级：

- 系统级：`03_任务技能/01_系统级/index.md`，定义跨小说的审查和规则维护流程。
- 共用小说级：`03_任务技能/02_小说级/index.md`，定义项目状态、回填、章节对账和验收流程。
- 本书配置：各小说 `03_任务技能/index.md` 与 `本书技能配置.md`，只写本书差异。

技能负责“如何执行”；模板负责字段；写作规则负责约束；小说数据负责内容。技能索引和配置不是定稿数据，不参与正文设定引用。加载技能后仍必须遵守本文件的路由、引用、ID、状态和验收规则。

## 引用语法

所有模板中的"关联"字段，统一使用以下语法：

| 引用类型 | 语法格式 | 示例 |
|---------|---------|------|
| 关联角色 | `@人物.[姓名]` | `@人物.[示例人物名]` |
| 关联主角 | `@主角` | `@主角`（固定写法，无需姓名） |
| 关联势力 | `@势力.[势力名称]` | `@势力.[示例势力名]` |
| 关联伏笔 | `@伏笔.[伏笔ID]` | `@伏笔.V1-C03-001` |
| 关联资源 | `@资源.[资源名称]` | `@资源.[示例资源名]` |
| 关联区域 | `@区域.[区域名称]` | `@区域.[示例区域名]` |
| 关联地名 | `@地名.[地名]` | `@地名.[示例地名]` |
| 关联道义 | `@道义.[道义ID]` | `@道义.DY-001` |
| 关联古籍 | `@古籍.[书名]` | `@古籍.[示例书名]` |

**规则**：必须使用上述格式，名称大小写完全一致；上表示例仅为语法格式示范、非本小说预设对象，实际引用名称须与已定稿数据一致；对象确实不存在时，在文件末尾登记「待创建条目」：
   ```markdown
   ## 待创建条目
   - [ ] @人物.某某某（于第X章出场，需补充人物卡）
   - [ ] @资源.某某某（于第X章获取，需补充资源卡）
   ```
加载多个数据文件时检查引用；只在确认对象不存在时登记待创建，不得把未加载误判为缺失。

**引用解析状态**：
- **已加载且存在**：可直接引用。
- **已知存在但本次未加载**：保留原引用，不得登记为待创建条目；需要校验时再按需加载目标文件。
- **确实不存在**：在当前数据文件末尾登记「待创建条目」，并将当前任务标记为「待校验」，不得宣称引用闭合。

## ID 编号

ID 按卡片类型使用下表格式，不得自创变体：

| 卡片类型 | 格式 | 示例 | 说明 |
|---------|------|------|------|
| 伏笔登记 | `V卷号-C章节号-序号` | `V1-C03-001` | 章节必填，精确到埋设章 |
| 主角突破 | `BP-卷号-序号` | `BP-V1-001` | 章节信息记在突破卡"突破章节"字段 |
| 战斗结算 | `BT-卷号-序号` | `BT-V1-003` | 章节信息记在战斗卡"发生章节"字段 |
| 资源道具 | `RES-类别-序号` | `RES-DAN-003` | 类别枚举：DAN丹药/FAB法宝/CLI材料/LS货币(灵石)/GF功法/FU符箓/LIN妖兽(灵兽)/OTHER（前缀 LS/LIN 为历史兼容写法，现指货币/妖兽大类） |
| 道义条目 | `DY-序号` | `DY-001` | 全书唯一 |
| 待创建条目 | `TODO-序号` | `TODO-001` | 仅在数据文件"待创建条目"列表中使用 |

序号在同类卡片内连续递增，不跳号、不复用；未定章节可暂缺，回收或引用时补齐；卡片引用必须使用 ID。

## Agent 任务路由表

> 「必读模板」定义字段和行为；「必读数据」提供已定稿设定。模板决定怎么写，数据决定写什么。
>
> 数据位置：设定层（全书级设计：小说概念/主角档案/文风/核心道义/全书卷大纲）在 `01_设定/`，设定卡（资料层）在 `02_数据库/`，卷规划/正文/事件卡在 `正文卷N/`，状态台账在 `03_状态/`，云端合并输出在 `05_云端回填/`；表中路径省略小说目录前缀。

> **任务到技能映射**：路由表定义任务输入与产出；任务→主技能/回退策略的绑定关系以 `03_任务技能/02_小说级/index.md`「任务到技能绑定」为唯一权威来源。

> **Token 控制**：单次任务加载的模板文件不得超过 **4个**。只统计实际读取的卡片模板、写作规则和验收规则；系统指令不重复计数。超出则优先加载"必读"，将"可选"拆为子任务单独执行。数据文件按需读取，不以文件数量代替 Token 判断；阶段中间产物不得作为定稿数据。

> **前置阻断**：任务路由表中的必读数据必须全部为「定稿」。任一前置数据缺失、状态不是「定稿」或引用未闭合时，Agent 只能输出阻断报告（缺失项、当前状态、下一步任务），不得用假设、占位内容或旧提示词继续生成。

> **提示词时效**：`04_提示词/` 中的提示词是可重新生成的执行缓存，不是永久有效的数据副本。每次交付云端提示词前，必须依据当前 `00_进度.md` 和最新定稿数据重新拼装；已有提示词若内联数据或前置状态已变化，禁止直接执行。

> **按需追加**：单章先有 `07_单章细纲模板`；含抉择/感悟追加 `10_事件与感悟卡模板`，含战斗追加 `08_战斗结算模板`，含突破追加 `09_主角突破卡模板`，含古籍追加版权规则，设计资源追加资源规则。

> **分类拆分规则**：多实体/查表型分类（修炼体系、地理区域、势力组织、资源、书籍库）数据产出**合计 >1KB 时**，按各模板「层级结构与文件拆分」定义的粒度拆分为「总索引 + 子文件」（≤1KB 保持单文件；地理区域按世界→区域→地名、书籍库按每书一文件恒拆分，不设 1KB 阈值）；加载时只读「总索引 + 涉及条目文件」，按需取分支，禁止整目录全量灌入。**增量追加**子条目（新增体系/世界/区域/地名/势力/类别/物品卡/书籍）时，须同步在父文档（总索引或上一级文件）索引表追加对应行与文件链接，逐级补链，不得只新增子文件而遗漏父索引。

> **查表型数据**：`02_数据库/01_修炼体系/`（总索引+每体系一文件）、`02_数据库/04_资源/`（总索引+每类别一文件）为大型查表文件，除卷大纲/新体系设计等需全量对照的任务外，一律**按需取条**——只读本章/本事件涉及的体系、资源条目文件，禁止整文件加载进上下文。

> **单章基线**：常驻 `01_系统指令 + 00_通用写作规则 + 00_文风_XX（本书所选文风） + 00_主角档案`；不替代路由必读数据，其余按需加载。

> **注意**：`05_开篇三章设计指南` 仅在**第一卷**的卷大纲设计时作为附加模板加载，其他卷不使用。

> **必读数据覆盖检查**：新增或修改路由表任一任务行前，先展开该任务对应的全部「必读模板」，列出模板中所有会产生 `@引用` 的字段；「必读数据」列必须逐一覆盖这些引用可能指向的上游分类总索引，不得遗漏。引用同名不同颗粒度的文件时（如全书级"全书卷大纲"与分卷级"卷大纲"），必读数据列必须写完整相对路径，禁止用简称，避免被误认成同一文件。

## 战斗流程

涉及主角的战斗按 `08_战斗结算模板` 执行：**战前设计 → 正文 → 战后结算**；必须交代动机、理念/互克、代价、伤亡和消息传播。

---

## 单章生成后一站式自检清单

> **唯一校验入口**：正文生成后执行 `00_通用写作规则` 第八章（+ 本书所选文风模板补充项）；全部通过后方可存档。
>
> 各层级校验项（结构层/爽感与压抑层/数据层/版权层/主角人设层/资源与经济层/事件设计层）已全部收敛到 `00_通用写作规则`（风格层以所选文风模板为准），本文件不再重复列出，避免规则多源、口径不一。
